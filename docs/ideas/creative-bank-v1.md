# 一、现有玩法变体（16 条：S1 ×8 + S2 ×8）

## V1-S1-01 · 1v1 指挥官决斗（模式）

- **玩法核**：去掉队友变量，3 车道收窄为 2 车道的镜像纯策略博弈，段位感从"配合"转向"算路"。
- **成本**：低——sim 席位模型 `team=seat%2` 现成，seats 4→2 + 车道表参数化即可；协议/客户端零改动。
- **来源依据**：〔设计〕slg 设计书 §1.1 车道制 1D + §6 mode 字段（`2v2-commander` 本就是声明参数）；〔QA〕GAMES-48 QA2 延迟对照臂证明单人决策链路干净（无队友噪声），适合做纯策略排位入口。
- **PM 决策建议**：**采纳追踪**——竞技层最小入口，建议随"模式扩展单"（单链 #11 弹性位）落地，与 L-11 排位分议题解耦。

## V1-S1-02 · 围城防守 PVE 波次模式（模式）

- **玩法核**：真人+Bot 守基地抗 10 波 AI 军团，出兵/技能/集结塔防化复用，第 10 波是双车道 heavy 洪流。
- **成本**：中——需 PVE 波次脚本（查表策略已有 `macro-push` 先例）+ 波次数值表；无需新协议（Bot 走既有 brain 接口）。
- **来源依据**：〔QA〕GAMES-44 QA1 A3 剧本实测 3×competitive tick8 快攻 3 分钟内拆挂机方——"被压迫"体验已量化存在；〔设计〕FEEL GAMES-47 的连杀横幅/受击脉冲/基地裂纹三档贴图，PVE 反馈件齐备。
- **PM 决策建议**：**采纳追踪**——休闲留存面（输赢压力低于 PVP），单链 #11 候选首位。

## V1-S1-03 · 闪电战 Blitz（规则）

- **玩法核**：CP 增速 ×2、积分线 400→250、maxTicks 2700→1200——2 分钟一局的高压快棋，feed 刷局节奏。
- **成本**：低——纯数值参数档（CP 速率/SCORE_MAX/maxTicks 均为 sim 常量），进房 mode 参数化一并交付。
- **来源依据**：〔QA〕GAMES-58 STRESS B 组 45 分钟极限局（ts=16×27000，漂移 ≤10 tick）证明局长弹性极大且稳定；〔玩家〕设计 §1.3 局长 2.5-4 分钟在竖屏 feed 场景偏长，"3 分钟军团快攻"卡片文案呼唤更短变体。
- **PM 决策建议**：**采纳追踪**——低成本高感知，mode 参数化框架的首个验证变体。

## V1-S1-04 · 兵种禁用轮换（规则）

- **玩法核**：每局 seed 派生随机禁 2 兵种，逼玩家走出 inf→razor→arty 惯性套路，克制三角被迫重组。
- **成本**：低——出兵卡遮罩 + sim 校验拒绝；seed 纪律（fnv1a(roomId) 派生禁用表）现成。
- **来源依据**：〔QA〕GAMES-46 BOT 深化后 balanced 档仍固定轮换 inf→razor→arty（设计 §4 表），真人同样易固化策略；〔设计〕§2.1 数值校核自述"克制三角保证无废兵"——禁 2 兵后三角破缺，重玩价值上升。
- **PM 决策建议**：**采纳追踪**——与 V1-S1-03 同属 mode 参数族，一并交付。

## V1-S1-05 · 峡谷双桥新地图（地图）

- **玩法核**：车道 3→4，中央十字焦点双信号塔——地图从"对称无先手"变为"焦点争夺先手博弈"。
- **成本**：中——地图布局是 sim 常量表，但 bot 车道选择逻辑要适配（competitive 最弱点算法按车道计数，通用性待验）；需确定性回归。
- **来源依据**：〔设计〕§1.1 "双方到点距离相等——无先手不对称"是有意取舍，变体图是"不对称但均衡"的实验位；〔QA〕GAMES-59 孪生房 166=166 事件逐条相等的确定性基线，让地图变体的回归验证成本极低。
- **PM 决策建议**：**搁置**——等 V1-S1-01/03 验证 mode 参数化框架后再上地图变体（先规则后地图的次序纪律）。

## V1-S1-06 · 战报回放与集锦分享（社交层）

- **玩法核**：终局输入日志重放 30s 精彩集锦（开战/转折/终结三段自动剪辑），结算页一键重看 + 摘要卡。
- **成本**：中——回放格式已冻结（{seed, tickMs, inputs}），差回放器 UI + 输入日志归档存储（JSONL 轻量）。
- **来源依据**：〔设计〕§5.3 明文预留"结算页战报回放共用确定性回放机制（排 VIS 单链 #9）"——既定排期项，本条重申并扩展分享面。
- **PM 决策建议**：**采纳追踪**——本就是单链 #9 范围，建议 VIS 后续单合并交付（勿单开）。

## V1-S1-07 · 队友指挥标记 ping（社交层）

- **玩法核**：2v2 长按己方车道发"进攻/撤退/集火此塔"标记，队友屏幕高亮；Bot 队友可读标记并响应（陪玩模式扩展）。
- **成本**：低——走 events 通道广播（{k:'ping',seat,lane,row}），零协议变更（游戏级事件扩展先例=slg keys 壳）。
- **来源依据**：〔QA〕GAMES-46 陪玩模式（真人静默 >150 tick bot 接管节奏）实证 2v2 真人+bot 协作是常态场景；〔玩家〕bot"带躺不抢戏"体验好，但缺"指挥队友"的表达面——ping 补协作语言。
- **PM 决策建议**：**采纳追踪**——社交深化低价位，FEEL 后续单候选。

## T3-A · 帝国萌芽：双表盘分层叙事（S3 主轴）

- **亮点核**：玩家同时看到"城"（状态同步实时成长）与"军"（帧同步对局）两个节奏盘，双指捏合切换宏观/微观镜头——把 S3 混合同步的技术分层直接变成玩法叙事。
- **成本**：中——两层 UI 状态机 + 镜头切换；协议按 roadmap S3 行"分层协议文档化"要求走设计书冻结。
- **来源依据**：〔平台〕roadmap §2 S3 行深要求"建设层用状态同步，战斗层用帧同步"；〔平台〕S1（帧同步 RTS，10/10 单链收官）+ S2（状态同步常驻镇，QA2 全过）两款已实证的拼接位——T3 是两者的合体首证。
- **PM 决策建议**：**采纳追踪**——T3 设计书单的差异化主轴，建议列为设计书 §1 定位句。

## T3-B · 帝国萌芽：兵营即兵种池（建设=军事）

- **亮点核**：城里造什么兵营，战场就能出什么兵——建设策略直接决定军事策略，两循环互相咬合而非并列。
- **成本**：低——S1 克制三角/三阶数值表/数值校核方法全套搬迁；建设产出只需映射到出兵卡可用集。
- **来源依据**：〔设计〕slg 设计书 §2.1 克制三角（inf→arty→razor）"保证无废兵"校核 + §1.2 基地阶决定出兵卡档（T1/T2/T3）——"建设决定兵"在 S1 已是隐藏第四循环，T3 把它扶正。
- **PM 决策建议**：**采纳追踪**——设计书数值节直接复用 S1 校核框架。

## T3-C · 帝国萌芽：联盟互助线（社交层）

- **亮点核**：盟友间"送线不抢线"——资源援助走 S2 让矿礼貌层同款机制（协作为常态、竞争为内容）。
- **成本**：低——礼貌层判定（目标节点 120px 内有真人则让 20 tick）代码级可搬。
- **来源依据**：〔设计〕mmo 设计书 §4 让矿礼貌层 + 决策 #8"礼貌是常态、抢夺是内容"；〔QA〕GAMES-53 §5 礼貌专项局实测（持握果位 25s，4 勤恳在场抢采 0 次）。

- **成本**：中——前端为主；数据 = stats 聚合 + 徽章（依赖 L-03）。
- **来源依据**：〔平台〕策划案-v2 G12（我的页无封面）/G7（跨设备）既列缺口；〔玩家〕匿名访客制下"生涯感"是零账号体系里最接近身份的载体。

## L-11 · 排位天梯（赛季段位分）

- **玩法核**：竞技模式排位分与段位徽章，赛季末定格。
- **成本**：高——匹配池 + 分数模型 + 防投机判定。
- **来源依据**：〔QA〕GAMES-46 mercy 让力参数（triggerGap 150/releaseGap 75 滞回）实证 Bot 能按分差调强度——是天生的匹配缓冲器（真人稀疏时 bot 垫位不碾人）；〔平台〕但策划案 §1 边界"不做账号"，访客匿名制下排位分无稳定载体。
- **PM 决策建议**：**否决**（v1 阶段）——匿名访客制与排位载体冲突；账号体系立项后随 L-02 完整版重启评估。

## L-12 · 平台代币与商店

- **玩法核**：跨游戏代币（贡献/战绩产出）兑换装饰（皮肤/铭牌/表情）。
- **成本**：高——经济系统 + 防刷（bot 刷分是已知风险面：三档 bot 行为可复算=可被脚本化）。
- **来源依据**：〔平台〕策划案-v2 §1 边界明列"不做支付"；〔设计〕S2 个人贡献余额已是游戏内货币先例（建筑花费从余额支付）。
- **PM 决策建议**：**否决**（v1 阶段）——踩"不做支付"红线边缘；装饰需求用成就解锁（L-03）达成同等体验，无经济系统风险。
