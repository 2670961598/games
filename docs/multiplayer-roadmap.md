# 联机游戏宇宙作战图（E6 · 2026-09-26 制作人指令）

> 制作人指令原文要点：提供第二个界面，里面都是联机游戏，滑动可见正在对战的对局，点击立刻加入；目前单机环境需 AI 补位对手；**联机游戏 20 款以上**（不计难度档），覆盖 MMO/SLG/FPS/MOBA 等不同品类；服务器侧帧同步/状态同步/混合/物理等**技术面全覆盖（可以不深，但覆盖必须全）**；按品类开多个长期单，长期单随进展持续派生新单，不搞一张单从头做到尾。

本文是 E6 战役的唯一流程与设计事实源；SOP v2（docs/quality-pipeline.md）的质量红线与波次纪律全部适用。

## 1. 总体架构

```
浏览器 ──HTTP──▶ :4399 静态服务（现状不动：125 款单机 + 平台首页）
   │                 └── multiplayer.html 联机大厅（第二界面）+ 各联机游戏页
   ├──WS/HTTP──▶ :4400 实时网关（新独立进程，HOST=0.0.0.0，nohup 常驻同口径）
   │                 ├── 房间管理器（rooms/seats/生命周期 waiting→live→ended）
   │                 ├── Bot 宿主（服务端无头跑 AI 对局，常驻若干"正在对战"房间）
   │                 ├── 对局流水 API（GET /api/matches，CORS *，大厅轮询/推送）
   │                 └── 帧广播器（lockstep 帧分发 / snapshot 分发，按游戏协议）
   └──SDK───────▶ games/_shared/net.js（连接/重连/时钟同步/输入上报/帧接收/ping 显示）
```

关键决策：
- **网关独立进程独立端口**，绝不触碰 :4399 存量服务（红线）；重启口径与 :4399 相同（nohup 常驻）。
- **"正在对战"= 真实存在的 Bot 房间**：Bot 宿主为每个已上线联机游戏常驻 1-3 个 AI 对局，大厅 feed 实时展示；玩家点击加入 = 通过 WS 取一个 Bot 席位（旁观→接管或下一局入座），秒进。
- **AI 补位是常态**：真人不足时 Bot 自动补满席位；真人加入时 Bot 让位。Bot 分三档水平（休闲/均衡/竞技）。
- LAN 可玩：WS/HTTP 均绑 0.0.0.0，客户端用 location.hostname 自适应。

### 4.2 api-check 通用化（M1 交付，制作人指令：操作都通过 API 输入、验证可玩）

- 每款联机游戏在 game.json 声明 `net.api`：操作清单（op → WS 输入消息）、胜负条件（状态断言）、测试剧本（deterministic seed + bot 档位 + 假时钟）。
- 网关测试管理 API：POST /api/test/room（隔离测试房+指定 seed/bot）、POST /api/test/input（注入操作）、GET /api/test/state（读对局状态）——**不依赖浏览器即可驱动整局游戏**。
- `node scripts/api-check.js <gameId>`：按剧本注入全部操作→断言状态迁移（能开始/能赢/能输/操作→状态延迟<100ms/重连恢复），JSON 报告落盘；浏览器仅用于 visual 支柱。
- **每张 QA 单必跑 api-check；DEV 单自跑通过才可交付。**

- 派生节奏：M0 合并后，按 T1→T7 顺序各开首款波次单（D 设计书先行）；每轨道首款合并后才开该轨道第二款。
- 并发约束：core 泳道同时仅 1 worker；联机单与 E1 单据在泳道内排队，M0 优先。
- 每款联机游戏交付时同步登记 docs/game-quality.json（复用档案骨架，新增 `net.tech`/`bot` 字段）。

## 6. 里程碑

- **M0 联机基座**（关键路径）：网关 :4400 + 房间管理 + Bot 宿主 + feed + net.js SDK + multiplayer.html 大厅 + 参考游戏（净斗坦克 lite，2Bot 补位）端到端跑通。
- **W1 波**：T1-T7 各首款（7 款）——同步技术矩阵 7 类全部首实证。
- **W2-W3 波**：各轨道第二、三款 → 累计 21 款。
- **横向**：大厅体验统一（对局卡片视觉/观战/快捷语）、跨游戏联机档案（战绩页）、服务器压测报告（单进程 50 房）。
- 每波回填知识库（波次报告/案例/工具手册），SOP 修订镜像本图。

## 7. 参考实现口径（worker 必读）

- 服务端：Node 原生 `http`+`ws`（零新依赖优先；确需 ws 库须 vendor 进 repo 并说明）。游戏逻辑模块化（每游戏一个 server 端 sim 文件），Bot 宿主统一接口 `spawnBot(gameId, level) → Bot`。
- 客户端：`games/_shared/net.js` 唯一网络出口；联机游戏页与单机游戏同规范（375×667 安全区/seed 纪律/上报协议）。
- 帧协议：JSON 帧（覆盖优先，性能后优化）；S1 帧序号+输入向量，S2 快照+脏实体增量，S5 操作+裁决结果。
- 房间生命周期与 feed schema 由 M0 冻结为 `docs/net-protocol.md`，后续游戏照协议接入（协议变更需 PM 批）。
