## 1. 玩法循环

**定位**：一局 5-8 分钟的双人元素卡牌对战——**出牌/攻击/技能全部服务器裁决**（roadmap 技术矩阵 S5 本格首证：服务器裁决回合 + 超时托管 + 断线重连续玩）。共享 3×3 棋盘上，随从与随从做邻居触发元素反应：组合优于数值（T5-B 亮点核）。离开/断线时 Bot 按你卡组的风格续打到终局，回来再看战报——牌局不断（T5-A 差异化主打）。竖屏 375×667，单拇指拖牌上阵、点选目标。

### 1.1 对局时间轴（5-8 分钟，room tick=10ms，maxTicks=48000）

```
选英雄(10s) ─ 换牌(30s) ─ 抢格铺场 ─ 反应连携 ─ 收官斩杀 ─ 硬顶
   waiting     mulligan    回合1-3     回合4-7     回合8+     8min/疲劳
              双方各定起手  占格子立随从  邻接反应/换血  直伤斩杀/疲劳递增
回合制：turnStart(抽牌/回蓝) → play(出牌/攻击/技能, 30s) → endTurn → 对方
```

- **选英雄**：waiting 期 10s 内双方 `pick` 英雄（4 位，见 §2.3）；超时由 seed 流随机定。英雄决定技能/被动与整套预构筑牌组（§2.4）。
- **换牌**：起手 先手 3 张 / 后手 4 张 + 1 张 0 费「元素微粒」；30s 内点选保留任意张，其余洗回重抽（同 seed 流，确定性）。
- **抢格铺场**：随从部署到共享 3×3 的空格（每方上限 4 只）——位置即战术：近敌行可冲脸、后排/角落免近战、邻接己方异系随从触发反应（§1.3）。
- **反应连携**：中期的组合解谜——水+火蒸气清场、风+雷连锁点杀、卡位阻断对手的反应邻接（§1.4 反应表）。
- **收官**：直伤法术斩杀（斩杀线见 §4.2）或牌库抽空进入疲劳递增（1,2,3…）逼出终局。
- **回合预算**：正常局双方各 6-10 回合；每回合人类 8-20s（30s 计时）→ 5-8 分钟。硬顶：maxTicks=48000 → HP 高者胜（相等 draw）；疲劳通常更早收口。

### 1.2 回合状态机（服务器权威裁决，S5 本格语义）

```
mulligan(30s 双方提交 keep) ──▶ turnStart(seat) ──▶ play(30s) ──endTurn──▶ turnStart(对方)
                                    │                  │
                                    │ 润泽回血/抽1张     │ play/attack/heroPower 任意次序
                                    │ (疲劳判定)        │ 30s 超时 → 托管代打整回合(T5-A)
                                    ▼                  ▼
                              部署即定位           任意伤害事件 → 英雄 HP≤0 → ended
```

- **turnStart**（服务器逐项定序）：①回蓝 `mana.max=min(8,++n), mana.cur=mana.max` ②潮汐被动回血 1 ③抽 1 张（牌库空 → 疲劳计数 +1 并扣等量英雄血）④全体随从 ready（冻结标志见 §2.5）。
- **play**：仅当前回合席位可操作；op 任意次序任意次（受费用/格子/规则约束），每条 op 由服务器即时裁决回 `ruling`（事件 + 全量个性化 state，§5.2）。
- **超时托管**：30s 到点未 endTurn → 托管 Bot 以 casual 牌风**代打完整回合**（T5-A 随手托管）；玩家在线则下回合夺回。**连续 3 个全超时回合（零 op）→ afk 认负**（防白嫖；pool 先例）。主动托管（§1.6）与断线托管不受 afk 计数。
- **结算序固定（红线）**：每次 op 内部 ①校验/扣费 ②入格或施放 ③入场效果 ④反应（邻接格固定序扫描，§1.4）⑤伤害/死亡结算 ⑥英雄 HP≤0 终局检查——跨端一致的根。

### 1.3 共享 3×3 棋盘（T5-B 落地：位置即决策，无移动相位）

**单棋盘 9 格**（cell 0-8，行优先：行 0 顶=近**对方**英雄侧，行 2 底=近**己方**英雄侧；席位 B 渲染时翻转，服务器行号绝对）。双方随从同盘混布，每方上限 4 只——**空间本身是资源**：满员时 8 只挤 9 格，只剩 1 个空格。

| 规则 | 定义（sim 判据，全部显式字段） |
|---|---|
| 近战 melee | 仅可攻击**正交相邻**的敌方随从；位于**近敌行**（己视角顶行）时可直接攻击敌方英雄 |
| 远程 ranged | 可攻击任意敌方随从或敌方英雄，无位置限制 |
| 嘲讽 taunt | 敌方存在嘲讽随从时，一切攻击必须指向嘲讽（近战仍受邻接限制——无可达嘲讽则近战不可攻击） |
| 突袭 rush | 部署当回合即可攻击**随从**（不可打英雄）；次回合解禁 |
| 冻结 frozen | 被冻结随从在其拥有者的**下一个回合**不可攻击，该回合结束解冻（一次性标志） |
| 位置不变 | 部署后格子不可改（唯一例外：法术「迷踪步」传送，不触发反应） |

**设计裁定**：位置只在**部署时**选择、永久生效——没有移动相位/移动 op，把战棋的空间深度压进"出牌选格"一个动作里；后排/角落天然免近战（近战打不到非邻接格），近敌行 = 冲脸高风险高回报。攻击不受位置限制（除近战邻接），格子纯为**己方组合与空间封锁**服务——lite 的关键收窄。

### 1.4 元素反应表（6 对全覆盖，触发即结算——T5-B"组合优于数值"的机制化）

部署一个随从时，若其正交相邻存在**己方异系**随从，即触发反应——**自动触发、部署前 UI 预览辉光**（部署是自愿的，不想要感电就别挨着放）。多个相邻异系按**邻接格固定扫描序（上→右→下→左）**逐对触发，每对一次：

| 反应 | 元素对 | 效果（全部整数、确定性） |
|---|---|---|
| 蒸气 Steam | 水+火 | 对**全部敌方随从**各造成 1 伤害 |
| 连锁 Chain | 风+雷 | 对一名敌方随从造成 2 伤害（自动选 hp 最高，平局 cell 小），并对其正交相邻**敌方**随从各 1 伤害 |
| 引爆 Blast | 火+雷 | 对两枚反应随从**所在行**的全部随从（双方，含自身）各 2 伤害 |
| 迷雾 Mist | 水+风 | **己方**全部随从 +0/+2（含刚部署者） |
| 燎原 Wildfire | 火+风 | 对**敌方英雄**造成 2 伤害 |
| 感电 Surge | 水+雷 | 对**全部随从（双方）**各 1 伤害 |

引爆/感电的己方误伤是**有意的成本设计**：摆放时预判弹道，组合解谜的"解"就在这里。反应效果并入 §1.2 结算序第 ④⑤ 步（反应伤害同样走死亡结算）。传送（迷踪步）**不触发**反应——重排只为下一手部署做邻接。

### 1.5 费用与资源

- **法力**：起始 1，每回合 +1，**上限 8**；回合开始回满。卡费 1-6（§2 曲线）。
- **手牌**：上限 8，回合结束超出即烧毁（事件公示，对方可见张数）；抽牌动画见 §3。
- **疲劳**：牌库空时每次该抽牌 → 疲劳计数 +1、英雄扣等量血（1,2,3…）——终局保底。
- **英雄技能**：每回合 1 次，2 费（§2.3 四位英雄各异）。
- **先手补偿**：后手 4 张起手 + 「元素微粒」（0 费法术：本回合 +1 费，不入牌组、不可复制）。

### 1.6 单拇指操作映射（375×667 安全区，右手全程可达）

| 操作 | 手势 | 区位 | 说明 |
|---|---|---|---|
| 出牌（随从） | 手牌**拖**到棋盘空格 | 手牌区→棋盘全区 | 拖起时合法空格辉光（含反应预览色）；松手即部署，非法格回弹 |
| 出牌（法术） | 点牌→点目标 | 手牌区/棋盘/英雄像 | 点选后合法目标高亮呼吸；再点取消 |
| 攻击 | 点己方 ready 随从→点目标 | 棋盘 | 首点出攻击指示线（合法目标高亮）；再点取消 |
| 英雄技能 | 点技能钮→（如需）点目标 | 底栏 | 同上 |
| 结束回合 | 大钮 tap | 底栏右 108×48 | 计时最后 5s 钮红闪 |
| 托管 | 托管钮 tap | 底栏左 40×48 | 主动托管/夺回切换（T5-A：主动托管也是合法操作），托管中徽标呼吸 |
| 换牌/选英雄 | tap | 对应期浮层 | tap 切换保留态→确认钮 |

回合制下单拇指三动作（拖牌/点选/大钮）即全部操作面；所有点选两段式（选源→选目标），误触零成本。

### 1.7 胜负（先到者胜，reason 入 end 消息）

1. `lethal`：英雄 HP ≤ 0（伤害源可能是攻击/法术/反应/疲劳/爆牌无关——疲劳致死同 reason，scores 附疲劳数）。
2. `timeout`：maxTicks=48000 → **HP 高者胜**（相等 draw）。
3. `afk`：连续 3 个全超时回合（零 op 且超时）→ 认负。
4. `resign`：concede op 认负。`abandon` 沿用协议（全员离线 15s——本作常态是托管续打，仅双方皆断线且重连窗尽时触达）。

**v1 不做**（有意收窄，先例：roadmap §4.1"规则子集"）：自由构筑（四套预构筑，§2.4）、装备/武器、亡语之外的触发器类（仅入场/反应/攻击附效三类）、英雄攻击、多目标法术、连击连锁深度 >1（反应不在反应上再触发）。

## 3. 手感参数

### 3.1 反馈预算（红线：回合反馈 <100ms；本地表现 0ms）

| 环节 | 预算 | 实现 |
|---|---|---|
| 拖牌松手 → 卡离手 | **0ms（本地即时）** | 松手即以"待裁决幽灵"呈现（卡半透明悬停目标格），不等服务端 |
| op → ruling 回执 | ≤10 tick（100ms，服务端同钟） | 服务器逐 op 即时裁决（无模拟期），LAN 实测 RTT+裁决 <50ms |
| ruling → 棋盘落定 | 0ms | 收 ruling 直接渲染全量 state（离散态无插值）；reject 则幽灵回弹+震动 150ms |
| 回合切换反馈 | ≤10 tick + 本地 banner 0ms | endTurn ruling（对方 turnStart 事件）→「对方回合」横幅 500ms 非阻塞；轮到自己时「你的回合」+ 回蓝晶体逐颗点亮 300ms |
| 伤害数字 | 400ms 飘字（非阻塞） | 红字上飘+目标顿帧 1 拍（渲染层 60ms） |
| 抽牌动画 | 280ms 卡背翻入 | 手牌滑入 200ms——全部非关键路径（可继续操作） |

### 3.2 出牌确认与反应预览

- **拖牌即预览**：拖起随从时，合法空格呼吸辉光；**悬停某格时该格与将触发的反应对亮对应元素色环**（水+火→悬停格亮蓝红双色环），松手前的全部信息免费——出牌确认零弹窗（回合制 + 服务器校验兜底，误操作靠两段式点选回弹消化）。
- **攻击指示线**：点选己方随从后，从其格到每个合法目标画指示线（己方琥珀/对方青，虚线），非法目标压暗——嘲讽存在时自动只留嘲讽。
- **斩杀线提示**：敌方英雄 HP ≤ 己方可打脸伤害（§4.2 同式客户端复算，只用己方可见信息——合法）时，敌方英雄像红光呼吸 + 「可斩杀」角标（P1）——全档可见（裁量：休闲 CCG 的减负，不与 tier 挂钩；pool 瞄准辅助分档针对的是操作精度，此处是算术减负）。
- **托管徽标**：托管中头像挂「托管」徽标（P1），己方托管可一键夺回；对方托管时己方 UI 照常。

### 3.3 juice 清单

反应触发：全屏元素色横幅 500ms（六反应各一色一图标）+ 棋盘格受波纹 120ms；连锁闪电画折线 240ms；蒸气/感电全体白闪 1 拍；引爆整行震屏 150ms。随从死亡：碎裂粒子 300ms + 坟场计数 +1 飞入。英雄受击：像震 150ms + HP 条 tween 180ms；疲劳触发：紫色闪电+疲劳计数弹出。回合结束：手牌扇收拢 200ms。胜利：24 血条爆裂 + 四元素色粒子雨。

## 4. Bot 三档策略（卡牌 AI 新领域：出牌评估函数设计）

Bot 走网关 Bot 宿主统一接口（`spawnBot('element-duel', level)`），输出与真人完全相同的 `pick/mulligan/play/attack/heroPower/endTurn/host/concede` op（服务器权威校验，零特例通道）。**卡牌 Bot 是新领域**：决策不是连续几何而是组合序贯——本节给可执行评估函数。Bot 算术全整数，rng=mulberry32(fnv1a32(roomId)^0xC0DE ^ (seat+1)*0x9E37 ^ turnNo<<8)——同 seed 同决策（双跑剧本依赖）。

### 4.1 局面价值函数 V（balanced/competitive 共用核，整数权重）

```
V(S, seat) =
  Σ_own(m): 3·atk + 2·hp + pos(m) + (m.ready ? atk : 0)        // 就绪攻击力即时价值
− Σ_foe(m): 3·atk + 2·hp + pos(m) − (m.frozen>0 ? atk+2 : 0)   // 冻结折损
+ 4·ownHeroHP − 5·foeHeroHP                                     // 敌血更贵（进攻倾向）
+ 3·handCount + comboBonus                                       // 手牌=资源；combo 见 4.3
pos(m) = 角格(0,2,6,8)+2 ｜ 近敌行近战+3 ｜ 行1-2 远程+1 ｜ 嘲讽+2
```

**行动选择（贪心+模拟，无树搜索）**：枚举当前全部合法单动作 A（每张可付费牌 × 合法格/目标、每个合法攻击、技能、endTurn 作基线）→ 服务器 scratch 副本（全量 state 克隆，合法同 pool §4.3 先例）模拟执行 → ΔV = V(结果)−V(当前) → 取 argmax（平局按动作枚举序，固定）→ 循环至 endTurn 最优或无动作。预算：单回合 ≤3 轮 × ≤120 动作枚举 × 小状态模拟 ≈ 10³ 次整数评估 <5ms——30s 窗口余量万倍。

### 4.2 斩杀线计算（competitive 专属，闭式可达伤害）

```
D = Σ_ready 随从 atk × (远程 ? 1 : 所在近敌行 ? 1 : 0)      // 近战仅近敌行可及英雄
  × (敌方有嘲讽随从 ? 0 : 1)                                  // 嘲讽未清则板面伤害归零
+ 英雄技能直伤（mana≥2 且技能可指英雄：炎阳火弹=2）
+ 手中可支付直伤法术对英雄总量（FS1=4；TS1/FS2 不计英雄目标外溢）
若 D ≥ foeHeroHP → 斩杀模式：法术直伤英雄 → 技能 → 全部攻击指向英雄（忽略 V）
```

balanced **不做**此检查（V 的英雄项会偏进攻但不会倾倒资源斩杀——档位差有意保留）；competitive 每回合开始先查，命中即切换。

### 4.3 资源管理与 combo 检测（competitive 专属项）

- **comboBonus**：手中每存在一对"反应伙伴"（水+火 / 风+雷 / 火+雷 / 水+风…按反应表 6 对，可付费视角不区分）+6——鼓励攒组合而非零碎倾泻。
- **组合部署规划**：play 枚举已含反应模拟（scratch 执行 §1.4 全表），ΔV 天然偏好能触发蒸气/连锁的格位——**combo 检测 = 模拟驱动，不写手写模式**。
- **曲线纪律**：V 含 handCount（+3/张）与未花费用隐含损失（endTurn 基线 ΔV 落后于出牌）→ 贪心自然满费；v1 不做"留牌等 combo"的深谋（若本轮无combo 且有替代出牌，照常花光——深谋留 BOT 深化单调参）。
- **清嘲讽纪律**：敌方嘲讽存在 → 攻击枚举只剩嘲讽（规则强制），V 的 pos(嘲讽+2) 使解场优先。

### 4.4 三档参数表

| 参数 | casual 随手 | balanced 价值评估 | competitive 斩杀+combo |
|---|---|---|---|
| 决策时机 | 0.8-1.8s 拟人延时 | 1.5-2.5s | 2-3s |
| 出牌 | 可付费牌随机（权重=费用，偏大件） | §4.1 贪心 argmax | §4.1 + §4.2 斩杀覆盖 + §4.3 comboBonus |
| 目标选择 | 随机（30% 英雄/70% 随从） | 模拟 argmax | 模拟 argmax；斩杀期全指英雄 |
| 攻击 | 随机合法目标（30% 打脸） | 模拟 argmax（解场偏） | 同左 + 斩杀线覆盖 |
| 换牌 | 全保留 | 保留 ≤2 费牌 + 反应伙伴对 | 同左 + 无 2 费以下重抽 |
| 选英雄 | seed 随机 | seed 随机（均衡池 H1/H2） | 对位反选表（对方 H0→H1 潮汐，其余→H3） |
| 预期胜率（对 balanced） | ~25-35% | 基线 | ~65-75% |

### 4.5 托管 Bot（T5-A：按你卡组的风格续打——断线/主动托管用，非三档）

参数化自**被托管者牌组配方**（server 读 deck 常量，合法）：

- `faceBias`：均费 <2.6（炎阳/疾风）→ 敌英雄项权重 ×1.5（5→7）；均费 ≥2.8 → 解场偏（敌方随从项 ×1.3）。
- `comboBias`：配方含 ≥4 对反应伙伴（查 §2.4 表）→ 启用 comboBonus。
- 脑体 = balanced 核 + 上两偏置；**超时单回合代打 = casual 牌风**（随手托管语义），断线/主动托管 = 本节牌风化 balanced——两档区分是"偶发超时别太聪明、长期托管要像本人"。

### 4.6 牌桌评语（T5-C：赛后 Bot 一句评语，确定性查表）

终局 ruling 附 `quip` 字段（bot 对真人打法的评语），按优先级取首命中（全部来自日志可算统计，零随机）：

| 优先级 | 条件（本局统计） | 评语示例 |
|---|---|---|
| 1 | 反应触发 ≥5 | 「五次元素反应——棋盘在你手里会发光。」 |
| 2 | 斩杀回合 ≤6 且胜 | 「第{N}回合的斩杀，我上一回合就该嗅到。」 |
| 3 | 烧牌 ≥2 | 「手牌溢出两张，下次试着早点倾泻。」 |
| 4 | 治疗总量 ≥8 | 「你把血线攥得很紧，打得像个老潮汐。」 |
| 5 | 反应触发 ≤1 且局 ≥8 回合 | 「元素是孤立地打出去的——让它们做邻居试试。」 |
| 6 | 嘲讽解场 ≥4 | 「我的攻势都撞在你的墙上。」 |
| 7 | 兜底（按 Bot 档） | casual「陪打愉快，下次我还随手。」/ balanced「势均力敌，再来。」/ competitive「记住这条斩杀线。」 |

## 5. S5 回合权威协议细节（核心节）

本节在 net-protocol v1.1 冻结框架内落 element-duel 实现细则。S5 扩展位（`t:'op'` 上行 / `t:'ruling'` 下行）已由 pool-physics 复用实证——本作是 **S5 本格首证**（回合制原生语义：回合状态机/隐藏信息/托管），并把 §6 S5 行补注为"S5 本格实证（element-duel）"。镜像 S4 先例新增游戏级声明块 `welcome.room.duel = {engine:'element-int-v1', hash}`（hash=fnv1a32(卡池+反应表+常量 JSON)，版本护栏：不符 → 客户端提示刷新）。DEV 单随交付回填 net-protocol §6（GAMES-74 O1 文档化先例）。

### 5.1 消息规格（JSON 文本帧）

**上行（op 通道）**：

| 消息 | 字段 | 说明 |
|---|---|---|
| `op{pick}` | `{t:'op', k:'pick', hero:0..3}` | waiting 期选英雄（10s 超时 seed 定） |
| `op{mulligan}` | `{t:'op', k:'mulligan', keep:[bool,…]}` | 保留起手子集（与手牌等长），其余洗回重抽 |
| `op{play}` | `{t:'op', k:'play', card:<手牌序号>, cell:0..8?, tgt?}` | 出牌：随从带 cell；带目标效果/法术带 tgt（schema 见 §2.2 末） |
| `op{attack}` | `{t:'op', k:'attack', from:0..8, tgt:{s,c}}` | 随从攻击（c=-1 为英雄）；校验 ready/邻接/嘲讽/冻结 |
| `op{heroPower}` | `{t:'op', k:'heroPower', tgt?}` | 英雄技能（H0/H1/H3 带 tgt） |
| `op{endTurn}` | `{t:'op', k:'endTurn'}` | 结束回合 |
| `op{host}` | `{t:'op', k:'host', on:bool}` | 主动托管开关（T5-A）；on=false 或任意合法 op 即夺回 |
| `op{concede}` | `{t:'op', k:'concede'}` | 认负 → end{reason:'resign'} |

**下行（ruling 单通道 + end）**：

| 消息 | 字段 | 说明 |
|---|---|---|
| `ruling` | `{t:'ruling', frame, turn, seat, phase:'mulligan'\|'play', timerMs, events:[…], state, quip?}` | 每 op 裁决 + 回合事件（turnStart/endTurn/超时/疲劳）。events：`{k:'draw'\|'burn'\|'play'\|'spell'\|'attack'\|'damage'\|'heal'\|'death'\|'reaction',rt:…}\|{k:'frozen'\|'heroPower'\|'turn'\|'endTurn'\|'fatigue'\|'host'\|'mulligan'\|'timeout-turn'\|'reject',why}` |
| `end` | 协议 §4.2 同形 | reason ∈ `lethal\|timeout\|afk\|resign\|abandon`；scores={A:{hp,reactions,fatigue},B:…}；quip（§4.6） |

**state（个性化，见 5.3）**：`{heroes:{0:{hp,mana,hero,powerUsed},1:…}, board:[9]，hand:{me:[cardId…], opp:{n}}, deck:{me,opp}, grave:{me:[…],opp:[…]}, fatigue:{me,opp}, host:{me,opp}, turn, seat}`。

### 5.2 零快照流：纯事件驱动（S5 比 S4 静止期更极致）

- **无 snapshot 消息**：卡牌无连续运动，状态只在 op/回合事件上跳变——每条 ruling 附**全量个性化 state**（~0.8-1.5KB），两次事件间带宽 = ping/pong 心跳。回合 3-6 条 op → 突发 ~5KB/回合，秒级静默——全目录最低带宽档。
- 帧号语义：room tick=10ms 照常推进（计时器基准），ruling.frame = 事件时刻 tick；`frame.ext.turn` 不用（回合态在 ruling 内，同 pool 裁定）。
- `$sync`/sync 纠偏 = 重发当前个性化全量（同 welcome 路径）。

### 5.3 隐藏信息与个性化 state（本作新面——目录首款迷雾下发）

- **手牌保密**：ruling 按连接个性化——己方见牌面，对方只见 `opp:{n}` 张数。mmo AOI 按视野裁剪是同范式先例（per-connection 视图），本作是**按角色裁剪**。
- 公开信息：棋盘 9 格、双方 HP/费用/牌库数/坟场（顺序公开）/疲劳数/托管标志。
- **观战**：双方手牌均隐藏（只张数）——防观战透视；终局 end 附 `reveal:{hands}` 全披露（战报审阅，T5-A 回来看战报的素材）。
- **确定性不受影响**：服务器持有 canonical 全量态（含双方手牌）；重放/双跑（5.6）用 canonical，个性化只影响下发视图。
- 裁决权威：一切判定（嘲讽/邻接/费用/目标合法）在服务器，客户端高亮只是引导——reject 回弹（§3.2）。

### 5.4 断线重连与托管（S5 深度要求：断线重连续玩——T5-A 差异化主打）

- 协议 §2 的 10s+1 拍窗沿用：`join resume{seat,token}` → welcome **全量个性化 state 一次性恢复**（手牌牌面/场面/坟场/牌库数/疲劳/回合归属/计时/托管标志）——手牌/场面/坟场全量（单据指定口径）。恢复 <1s。
- **托管语义（回合制天然加强）**：重连窗尽或主动托管 → §4.5 牌风化 Bot 接管**直至终局或回归**；托管不改 seat.kind（名册稳定，仅 `host` 徽标 + feed 外显），任意时刻 resume/合法 op 即夺回——**牌局不断**（T5-A 原文机制化）。
- 回合计时对断线方**不暂停**；超时单回合由 casual 代打（§1.2）；连续 3 全超时回合 afk 认负；双离线 15s abandon 收房（协议 §2）。
- 终局战报（回来看战报）：end.reveal + 事件日志重放（§5.6 输入日志）→ 结算页「战报回放」逐步演示双方回合。

### 5.5 服务器权威 RNG 与 seed 纪律（单据指定：双方牌序确定化）

- **派生链（冻结）**：`roomSeed = fnv1a32(roomId)`（测试房用 §8.1 `seed` 参数钉死）→ `deckSeed[seat] = mulberry32(roomSeed ^ (seat+1)·0x9E3779B9)` → Fisher-Yates 洗 §2.4 配方表 → 抽牌流按事件序消费同一流（换牌重抽继续消费）。
- **零隐藏随机**：sim 判定路径零 `Math.random`/`Date.now`（S1 §5 纪律照搬）；连锁反应自动目标/磁暴溅射等"随机味"效果全部是**确定性规则**（hp 最高/平局 cell 小）——本作判定路径根本无随机，随机只存在于洗牌与 Bot 拟人延时。
- Bot 决策流独立 seed（§4 头部公式），同 seed 同决策。

### 5.6 确定性与回放（重放 = 重放 op 日志）

- **canonical state**：服务器全量态（含双方手牌）；`stateHash = fnv1a32(serialize(state))`，serialize 键字母序、数组按固定序（board cell 序/hand 抽取序）。
- **输入日志**：`{seed, picks:[hero0,hero1], ops:[{frame, seat, k, …payload}, …]}`——重放器从 roomSeed 派生双 deck、逐条重放 ops 即整局复算（含托管 Bot：其决策固化在日志，回放不重跑 Bot——S1 范式照搬）。终态 stateHash 与在线一致 = 确定性证明。
- **红线清单**（QA 核验口径）：全整数态 ✓ 判定路径零随机（随机仅洗牌流）✓ 结算序固定（§1.2/§1.4）✓ seed 派生链冻结（§5.5）✓ serialize 键字母序 ✓ 个性化视图不影响 canonical ✓ 自动目标规则显式（hp 最高/平局 cell 小）✓。
- **双跑剧本**（A6 断言）：同 seed 同 op 序列两房 → 终态 hash 与输入日志逐字节相等。

### 5.7 房间生命周期与席位

- seats=2、`teams:{A:[0],B:[1]}`；room tick=10ms、maxTicks=48000；waiting（10s 选英雄）→ live → ended 沿用协议；`started` 附双方 hero 与初始 state。
- 旁观：`join mode:'spectate'` 收同一 ruling 流（双隐藏视图，§5.3）——回合制观战零成本（无重演义务），满员旁观无上限软约束沿用。
- 终局后 8s 展示窗沿用；`end.scores` 含 reactions 触发数（战报与 quip 判据源）。

### 5.8 延迟容忍、带宽与负载预算

- **200ms 延迟回合制天然容忍**（pool §5.6 论证同源且更强）：全部操作是离散 commit（拖/点一条 op），无逐帧输入、无瞄准精度、无插值——200ms 只体现在 ruling 回执（本地幽灵 0ms 兜住手感），回合节奏 10-30s 完全吞没。
- **带宽/端**：事件驱动，回合突发 ~5KB、静默期趋零（仅心跳）——全目录最低（低于 pool 球动期 4KB/s 持续档）。
- **网关负载**：无逐 tick 模拟（计时器外零计算），裁决为小整数操作；Bot <5ms/回合（§4.1）——单进程 50 房 STRESS 口径余量最大的一款，QA/STRESS 单按此复核。

## 附：设计决策记录（REPORT 引用）

1. **共享 3×3 单棋盘，非各自半场**——T5-B 的"3×3 出牌位"裁定为双方共享一盘：9 格对每方 4 只上限（满员 8/9）使**空格本身是稀缺资源**，先手抢格、卡位断对手反应邻接都有了对抗面；若各给半场则空间无争夺、反应无干扰，组合解谜退化成单人拼图。混布棋盘也把"近战邻接/近敌行冲脸"的战棋张力白送给卡牌（零新增 op）。
2. **位置=部署决策，无移动相位**——没有 move op、位置部署后不可改（唯一例外迷踪步法术）：空间深度全压进"出牌选格"一个动作，操作面维持单拇指拖牌。近战仅邻接、位于近敌行可直接打脸、后排/角落天然免近战——一条邻接规则生成三类位置价值。攻击不受位置限制（除近战邻接），格子纯为己方组合与封锁服务——lite 收窄的刀口。
3. **反应自动触发+部署预览，不做确认弹窗**——触发序固定（邻接格上→右→下→左扫描、每对一次）保确定性；自动化使 op payload 只需一个 cell 数（目标类反应用确定性规则：hp 最高/平局 cell 小），协议面最小；玩家用"放哪"表达是否想要反应（引爆/感电的己方误伤是设计的一部分）。
4. **隐藏信息个性化 state——目录首款迷雾下发**——pool 附决策 7（全量无迷雾）的反例：卡牌手牌必须保密。ruling 按连接个性化（己方牌面/对方张数），观战双隐藏、终局 reveal 全披露；canonical 全量态仍在服务器（重放/双跑不受影响）。mmo AOI per-connection 视图是范式先例。
5. **零快照流，纯事件驱动**——比 pool 静止期更极致：无连续运动就没有 10Hz 追帧的消费者（插值/校验/TV 都不需要——校验锚改为 canonical 重放 hash）。带宽/负载全目录最低，STRESS 余量最大。DEV 注意：客户端不跑 sim，渲染=ruling 全量渲染（离散态直染，无插值糊感）。
6. **deckSeed 双流派生 roomSeed，洗牌流单一消费**——`mulberry32(roomSeed ^ (seat+1)·0x9E3779B9)` 两流独立（互不可推）、抽牌/换牌重抽同流按事件序消费——双方牌序确定化（单据指定）且**换牌不破坏确定性**。判定路径根本无随机（连锁自动目标等全是确定性规则）——比"随机但 seeded"更强的一档。
7. **托管三层语义：超时单回合=casual、持续托管=牌组风格、主动托管=合法操作**——T5-A 与防白嫖的平衡：偶发超时别太聪明（随手杆先例）、长期托管要像本人（牌组配方参数化 faceBias/comboBias）、主动挂机是玩家权利（host op）；托管不改 seat.kind 保名册稳定与随时夺回。afk 只计连续 3 全超时回合。
8. **Bot 评估=整数 V 函数+scratch 模拟贪心，无树搜索**——卡牌动作空间（≤120 单动作）小到一次模拟即可估值，贪心循环至 endTurn 即完整回合；斩杀线是闭式可达伤害（近战仅近敌行可及、嘲讽未清归零、法术只计英雄有效部分）而非搜索；combo 检测=反应表全模拟进 ΔV + 手牌伙伴对加值（+6/对）——不写手写模式，反应表改了 Bot 自动跟上。预算 <5ms/回合，万倍余量。
9. **24 卡小卡池 + 4 套预构筑，不做自由构筑**——v1 平衡可控（四套对位表可全测）+ DEV 省构筑 UI/校验面；配方表即数值平衡的显式载体（曲线/均费/牌风列齐）。换牌（mulligan）保留——卡牌手感的头号减方差项，一个 op 一个相位换回。构筑/天梯留弹性单（§1.7 收窄清单）。
10. **疲劳递增 + maxTicks 双保底**——牌组 20 张/抽牌流约 17-20 回合耗尽，疲劳 1,2,3… 逼出终局（防无限拖延）；maxTicks=48000（8min）HP 高者胜是硬顶——两层保证"一局 5-8 分钟"的单据口径不可超。
