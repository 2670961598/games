## 1. 玩法循环

**定位**：一局 5-10 分钟的双人回合制战棋（可 Bot 补位）——8×8 棋盘、六兵种克制交锋、**行动点（AP）调度**、双据点攻防。操作面 = 点选单位 + 点选目标（竖屏 375×667 单拇指）。全部行动服务器裁决（S5），模拟引擎两端同跑同 seed 同果（S1）——确定性回放与双跑验证是本作技术叙事（roadmap §2 S1 行"展示确定性回放"继承）。

### 1.1 棋盘与地图（8×8，四图 seed 选一）

- **棋盘**：8 行×8 列，格 id `0..63`（行优先 `cell = r*8+c`）；`row 0` 顶 = B（对方）侧，`row 7` 底 = A（己方）侧。服务器行号绝对，席位 B 客户端渲染时 180° 翻转（element §1.3 同款）。
- **部署区**：A = rows 6-7（16 格）、B = rows 0-1（16 格），区内全平原；地形只出现在 rows 2-5（四图共同不变量，QA 可断言）。
- **地图库**：4 张手工图（§2.4），`mapId = roomSeed % 4`——同房双方同图，跨房由 seed 定（复玩性来源；seed 纪律见 §5.5）。
- **据点 ×2**：特殊格。**占据即翻转**：单位移动落定在据点格 → 该点 owner 立即变为该单位阵营（事件 `{k:'point'}`）；离开**保持**持有，被敌方占据才翻转。每回合开始，持有方每点 +1 占点分（§1.5 通道 2）。
- 全部四图满足 **180° 旋转对称**（`cell(r,c) ↔ cell(7-r,7-c)` 地形与据点双对称）——双方到点距离相等、无先手地形不对称（slg §1.1 无先手原则继承）。

### 1.2 一局时间轴（5-10 分钟；room tick=10ms，maxTicks=60000=10min 硬顶）

```
部署(20s 双方密置) ─ 揭示 ─ 抢点对峙 ─ 克制交锋 ─ 收官(歼灭/占点到线/回合计分)
   deploy 相位      reveal   回合1-4     回合5-12    回合13-16 或提前终局
```

- **部署相位**（20s）：双方在己方部署区自由摆 6 单位（互不可见——个性化视图 §5.3；客户端本地自由调整，一次 `deploy` op 提交全部 6 格）。双提交或 20s 到 → 揭示（全量盘面广播）→ 回合 1 开始。超时未交由服务端按**默认阵**代置（§2.4，确定性常量）。
- **回合制**：`turnStart(seat) → act(30s, ops 任意次序) → endTurn → 对方 turnStart`。每方 **16 个回合**封顶（`maxTurns=16`/方）。
- **先手补偿**：后手（seat 1 / B）开局占点分 **+1**（到线 10 分实际需 9——轻量补偿先手，element 后手 4 张起手先例；数值可调）。
- 节奏预算：每 seat-回合 = 4 次激活 × 4-8s ≈ 20-30s（30s 计时内）；预期双方各 6-12 个回合终局（合计 12-24 个 seat-回合）→ **5-9 分钟**；10 分钟硬顶由 maxTicks 兜底（超顶按 §1.5 通道 3 计分收官——"一局 5-10 分钟"由硬顶保证不可超）。

### 1.3 行动点制（AP=4/回合——本作核心取舍张力）

**每回合 AP=4；1 AP = 激活一个单位**。一次激活 = 该单位「移动 + 行动（攻击/技能）」的任意子集（只移动/只行动/先移后动）。编制 6 单位 > AP=4 → **每回合必有 2 个单位不动**——调度即策略（取舍先行，Bot 组合空间与局时控制同源）。

单位激活状态机（sim 事实字段 `u.phase`，turnStart 清零）：

```
idle ──move op──▶ moved ──attack/skill op──▶ done（激活完成）
  │                                        ▲
  └──────attack/skill op（不移直动）────────┘
```

- 首个触及 idle 单位的 op（move 或 attack 或 skill）**扣 1 AP** 并按上表推进；`moved` 后可补行动完成激活，`done` 后不可再动（无"攻击后再移动"）。
- endTurn 时 AP 未用完合法（弃权不罚）；deploy 相位无 AP 概念。
- **悔棋**：`undo` op 恢复**本回合 turnStart 快照**（≤1 次/回合，仅己方 act 相位）——位置/HP/死亡/据点翻转全部回滚（对手批量披露下零信息泄漏，§5.4）。

### 1.4 战斗结算（固定序——跨端一致的根）

**距离**：曼哈顿距离 `dist = |Δr| + |Δc|`；移动 = 正交逐步。**伤害一步式（全整数）**：

```
攻击 a → d 结算序（每次 attack op）：
① atk' = a.atk
② 克制（a 兵种克 d 兵种，§2.2 三角）→ atk' = atk'·320 >> 8        // ×1.25，Q8 定点
③ 冲锋（a=lance 且本次激活已移动 ≥3 格）→ atk' += 3
④ def' = max(0, d.def − (a=axe ? 2 : 0))                          // 破甲
⑤ 坚韧（d=sword 且 d.hp·2 ≤ d.maxHp）→ def' += 2
⑥ 奥术（a=mage）→ dmg = atk'（无视 def'）；否则 dmg = atk' − def'
⑦ 森林掩蔽（d 位于 forest）→ dmg −1
⑧ dmg = max(1, dmg) → d.hp −= dmg
⑨ d.hp ≤ 0 → d 死亡（事件 {k:'die'}），无反击；否则
⑩ 反击：dist(a,d) 在 d 的射程窗内（bow 窗 2-3：邻接不可反击）→ 以 d 为攻击方同式反算
   （反击方未移动——冲锋不适用；克制/破甲/坚韧/奥术/森林按类型照常生效），可击杀 a。
```

- **反击全强度、无追击**（v1 收窄：反击已是站位价值的一半，追击留给弹性单）。
- **技能**（active，走 `skill` op，均为一次性动作）：mage「火球」——射程 ≤3 任意格，目标格及其正交相邻格（十字 ≤5 格）内**全部单位**（敌我不分，含施法者若在溅射内）各 6 伤害（奥术：无视防；逐单位吃森林 −1、下限 1；按 unit id 升序结算）；healer「治疗」——射程窗 1-2 内一名己方单位 +8 HP（不超上限）。
- **同回合结算总序（红线，每局固定）**：`turnStart（清激活态→占点分结算→胜负检查）→ 逐 op（deploy→move→attack→skill→undo，按服务器接收序）→ endTurn（对手批量披露→换手）→ 全灭检查（每 op 后）`。

### 1.5 胜负（四通道，先到者胜，reason 入 end 消息）

| # | 通道 | 判定 | reason |
|---|---|---|---|
| 1 | **歼灭** | 对方 6 单位全灭（结算完成后检查；双方同时全灭 → draw） | `wipe` |
| 2 | **占点计分** | 每回合开始每持 1 据点 +1 分，**先到 10 分**胜（满占双点最快 5 回合——逼中场接团，slg §1.3 双通道同思路） | `score` |
| 3 | **回合计分** | 双方各满 16 回合（maxTicks=60000 先到亦同）→ `占点分 + Σ存活单位价值（§2.1 value 列）` 高者胜，平则 draw | `timeout` |
| 4 | 弃局 | 连续 3 个全超时回合（零 op 且超时收尾）→ 认负（防白嫖，element §1.2 同款）；主动认负；全员离线 15s | `afk` / `resign` / `abandon` |

### 1.6 单拇指操作映射（375×667 安全区，右手全程可达）

| 操作 | 手势 | 区位 | 说明 |
|---|---|---|---|
| 选中单位 | 点己方 idle/moved 单位 | 棋盘 | **纯本地**（零上行）：移动域高亮 + 射程内目标角框 + 底栏行动钮亮起 |
| 移动 | 点亮域内目标格 | 棋盘 | 路径箭头跟手预览（本地 BFS）；落定即 `move` op |
| 攻击 | 点行动钮「攻击」→ 点目标 | 底栏/棋盘 | 两段式：目标高亮含**伤害预演**（atk−def 客户端复算，§3.1）；确认发 `attack` op |
| 技能 | 点「火球/治疗」钮→（如需）点格 | 底栏 | 同两段式 |
| 撤销 | 「撤销」钮 tap | 底栏 | 恢复回合起点（≤1 次/回合，钮即灭） |
| 结束回合 | 大钮 tap | 底栏右 108×48 | 计时最后 5s 红闪 |
| 托管 | 托管钮 tap | 底栏左 40×48 | 主动托管/夺回（§5.4）；托管中徽标呼吸 |
| 部署 | 拖单位到部署区格 | deploy 浮层 | 本地自由重排，「出战」钮一次提交 |

全部点选两段式（选源→选目标），误触零成本；200ms 延迟下无瞄准精度诉求（离散 commit，S5 天然容忍，§5.7）。

### 2.5 数值校核（平衡讨论留档，slg §2.1 先例）

- **克制三角校核（主动伤:反击伤）**：斧→枪 `15−4=11 : 8−2=6`、枪→剑 `10−3=7 : 9−4=5` 主动交换占优；剑→斧 `11−2=9 : 12−3=9` 平手——axe↔sword 互伤等速下 axe 血厚（32>28）正面小优，**sword 的胜机在防守与残局**：HP≤14 触发坚韧（所受转 `12−5=7`）而克制反击恒 9——后期交换比反超（7 进 9 出）。一边平两边赚，无废边无死边。
- **TTK（先手无反击位/理想位）**：axe 杀 bow `12−1=11` 两刀、bow 打 axe `10−2=8` 四刀——且**开阔地 bow 无法风筝**：axe 威胁圈 = 移 2+射 1 = 3 = bow 射程上限，进入射程即进入还手圈（交替回合制下拉不开距离）——远程必须近战屏护（站位深度），lance 威胁圈 6（移 5+射 1）全场罩住 bow、冲锋贴脸 `8+3−1=10` 两刀收——机动是反远程的答案。
- **法师线**：mage 杀 sword `11`（无视防）三刀；近战收 mage（18 HP）：axe 两刀（22>18）、带冲锋 lance 两刀（10×2=20）、sword 三刀——玻璃大炮成立。
- **技能经济**：火球 1 AP ≤5 格各 6 伤（聚集 3 单位 = 18 伤，超过任何普攻）——代价是敌我不分 + 站位约束（散阵反制）；治疗 8/激活 vs 火球 6——消耗战与爆发的对位。
- **AP 张力**：6 单位 4 AP——保输出（sword/axe/lance/bow 4 激活）还是保功能（mage/healer 各占 1）每回合重排——调度深度即本作棋感。

### 2.6 升级/装备论证（v1 不做）

不做，理由三条：① 5-10 分钟局 + 16 回合封顶的刻度里，成长曲线只有 2-3 档感知，撑不起一套经济数值面；② 固定镜像编制 = 平衡完全可控（六兵种对位表可全测，element §附 9 预构筑同理），升级/装备引入后 QA 回归面从 6×6 对位膨胀到带成长的连续域；③ 确定性回放要求状态集封闭——升级依赖的击杀经验/经济收入会拉长结算链。点将（自选编制）、装备、晋升留**弹性单（单链 #11+）**，接口位：编制表本就是 sim 常量，换表即换 meta。

## 3. 手感参数

### 3.1 输入 → 表现延迟预算（红线：单位选中/移动路径预览/攻击确认 <100ms）

| 环节 | 预算 | 实现 |
|---|---|---|
| 单位选中 | **0ms（本地）** | hit-test 即响应：移动域 BFS + 射程目标角框（客户端跑 §5.1 同款确定性引擎，零上行） |
| 移动路径预览 | **0ms（本地）** | 拖动/悬停即画路径箭头（本地 BFS 复算，≤28 格 <1ms）；非法格压暗 |
| 攻击确认 | 本地伤害预演 0ms + op→ruling 回执 ≤10 tick（100ms，服务端同钟） | 两段式：目标高亮带预演数字（`max(1, atk−def)` 客户端复算，与服务器同式同果——S1 双端一致的消费面）；确认发 op，ruling 到即落定 |
| 悔棋 | ≤10 tick | turnStart 快照恢复，回执即全量 state |
| 回合切换 | ≤10 tick + 本地 banner 0ms | 对手 endTurn 批量披露到达 →「对方回合」横幅 500ms 非阻塞；轮到自己「你的回合」+ AP 灯珠逐颗点亮 300ms |
| 结算动画 | 非阻塞（可继续操作） | 见 §3.2 |

### 3.2 结算动画节奏（回合制 juice：确定性事件的演出层，不阻塞下一 op）

| 事件 | 节奏 |
|---|---|
| 攻击 | 攻方前冲 120ms → 受方顿帧 1 拍（渲染层 60ms）+ 伤害数字红字上飘 400ms |
| 反击 | 主结算后 300ms 接反击演出（同上式）——一来一回的"交锋感" |
| 击杀 | 单位溶解粒子 300ms + 价值飘字（+value）；克制击杀附加克制图标弹跳 |
| 火球 | 弹道 240ms → 十字溅射格逐格爆裂（按结算序 unit id 升序同步）+ 震屏 150ms |
| 治疗 | 绿色十字光 280ms + HP 条 tween 180ms |
| 据点翻转 | 旗帜翻转动画 400ms（阵营色 + 旗形双编码 §7） |
| **对手回合回放** | 对手 endTurn 批量披露到达后，事件序列按 300ms/激活 逐步演出（棋谱回放感——批量披露的体验补偿，§5.4） |

juice 细节：冲锋拖尾（moveSteps≥3 时路径残影）、AP 灯珠耗一熄一、濒死单位（hp·2≤maxHp）血条闪烁 + sword 坚韧盾徽亮起、连杀横幅（同一方单回合内 ≥2 击杀）。

### 3.3 辅助层（本地渲染，不入模拟——T4-B 分档哲学适配，§8）

- **威胁范围叠加**（默认开，设置可关）：选中敌单位显示其下回合可达+可击范围（红晕）——决策减负，纯客户端。
- **伤害预演**：攻击/技能目标格直接标预演数字（§3.1）。
- **路径箭头**：移动域内悬停画最短路（正交，遇障碍自动绕行）。

## 4. Bot 三档策略（战棋 AI 新领域：启发式评估 + 浅层前瞻——单据指定核心节）

Bot 走网关 Bot 宿主统一接口（`spawnBot('tactics-duel', level)`），输出与真人完全相同的 `deploy/move/attack/skill/undo(不用)/endTurn/host/concede` op（服务器权威校验，零特例通道）。Bot 算术全整数；rng 仅 casual 决策与各档部署定桩使用，流定义见 §5.5 派生链（`botRng[seat]`，按决策事件序消费——同 seed 同决策，双跑剧本依赖）；balanced/competitive 的 act 相位为**纯 argmax + 固定 tie-break（动作枚举序）——零随机**。

### 4.1 casual 随机合法（陪玩档）

每 AP 决策（拟人延时 0.8-1.8s/激活）：30% 且有合法攻击 → 随机单位随机合法目标攻击；mage 20% 火球随机射程内格、healer 20% 治疗随机受伤友军（有则）；否则随机 idle 单位移动到随机合法格（含烂走——向后/绕圈都是内容）；AP 耗尽或无合法 → endTurn。部署 = rng 在己方部署区随机 6 个互异格。预期胜率 vs balanced ~25-35%。

### 4.2 balanced 价值评估 + 地形（陪玩主力）

**局面价值函数 V（整数权重，element §4.1 范式移植 + 战棋域扩展）**：

```
V(S, seat) = Σ_own u: (2·hp + 4·atk + value + pos(u)) − Σ_foe u: (2·hp + 4·atk + value + pos(u))
           + 15·ownScore − 15·foeScore + 8·ownPtsHeld − 8·foePtsHeld
           − Σ_own u: risk_粗(u)

pos(u)  = max(0, 6 − 2·minDist(u, 任一据点))      // 据点趋近（占点通道的 V 投影）
        + (u 在 forest ? 2 : 0)                    // 地形加成（单据指定：均衡档吃地形）
        + (u 驻己方据点 ? 4 : 0)                    // 守点
        + (melee 且前进行 ≥2 ? 1 : 0)               // 近战前压
risk_粗(u) = max{ 敌 e 可达 u（e.move+e.range 粗界）: max(1, atk_e − def_u − forest) }   // 单最大威胁，不叠加
```

**行动选择（逐激活贪心，无树搜索）**：枚举当前全部单激活动作 A = 每个 idle 单位 ×（可达格含原地）×（每格可攻击目标 + 站位不动）≈ ≤28 格 ×(目标+1) × 6 单位 ≤ ~720 项 → 服务器 scratch 副本模拟执行（含反击，pool §4.3 / element §4.1 克隆先例）→ ΔV = V(结果)−V(当前) → argmax（tie-break 枚举序）→ 执行 → 重复 4 次（AP 尽）→ endTurn。预算：4 激活 × 720 × 小状态模拟 ≈ 3×10³ 次整数评估 <20ms——30s 窗口千倍余量。部署 = 默认阵（§2.4 T0）。

### 4.3 competitive 威胁计算 + 连招 + 棋形评估（竞技档）

balanced 核之上四件套：

1. **精确威胁图**：`threat(e) = BFS(e.move) ⊕ 射程窗膨胀`（bow 窗 2-3 空心环）→ 逐己方单位 `risk(u) = min(hp_u, Σ_{e 可击 u} max(1, atk_e − def_u − forest))`（**叠加封顶血量**——集火感知，替代粗算单项）。V 的 risk 项权重 −2。
2. **击杀确认（kill-secure）**：枚举时对"本次激活可击杀敌单位"的动作 ΔV 额外 +8（击杀奖励偏置）——防"打残不打死"的平局化；`risk` 封顶已隐含"残血单位价值骤降"。
3. **连招（combo）= 序贯激活涌现**：逐激活重枚举天然衔接"火球破血 → 近战收割"（火球落地后，收割成为下一激活的 argmax）与"axe 破甲 → bow 高攻贴低防"（scratch ΔV 自动偏好）——**不写手写模式**（element §4.3 模拟驱动先例：反应表改了 Bot 自动跟上）。
4. **棋形评估（formation）**：V 附加三项——己方 ranged 不在敌 melee 威胁图内 +4/个；healer 距最近受伤友军 ≤2 +3；melee 连线成排（同行相邻 ≥2）+2（防线整肃）。

**浅层前瞻（minimax 的 beam 替身）**：整回合贪心改束宽 3（每激活取 top-3 而非 argmax）→ 生成 3 套整回合计划 → 对每套计划 scratch 模拟**对方 balanced 整回合**（2-ply）→ 终态 V 取 argmax。预算 ×9 ≈ <100ms——30s 窗口三百倍余量；不 deeper（深度 2 已覆盖"这回合站位换下回合被打"的主风险面，深度收益递减、预算保护 STRESS 口径 §5.7）。

部署 = 三模板 rng 定桩（开局一次性，同 seed 同树——slg §4 开局树先例）：T0 默认阵 ｜ T1 左翼集中 sword(6,1) axe(6,0) lance(6,2) bow(7,1) mage(7,2) healer(7,0) ｜ T2 右翼集中（T1 的 c→7−c 镜像）。

### 4.5 托管 Bot（断线/主动托管用，非三档——T5-A 适配，§8）

### 5.3 消息规格（JSON 文本帧）

**上行（op 通道）**：

| 消息 | 字段 | 说明 |
|---|---|---|
| `op{deploy}` | `{t:'op', k:'deploy', cells:[{unit,cell}×6]}` | 部署提交（己方部署区互异格）；超时服务端按默认阵代置 |
| `op{move}` | `{t:'op', k:'move', unit:<id>, path:[cell,…]}` | path 正交邻接链（起点=当前格），步数 ≤ 移动力、途经可通行且无单位；首个触及 idle 单位的 op 扣 1 AP |
| `op{attack}` | `{t:'op', k:'attack', unit:<id>, tgt:<id>}` | 射程窗校验（含 bow 下限 2）；结算序 §1.4；完成该单位激活 |
| `op{skill}` | `{t:'op', k:'skill', unit:<id>, cell:<cell>}` | mage 火球（任意格 ≤3）/ healer 治疗（cell 上己方单位，窗 1-2） |
| `op{undo}` | `{t:'op', k:'undo'}` | 恢复 turnStart 快照（≤1 次/回合，仅己方 act） |
| `op{endTurn}` | `{t:'op', k:'endTurn'}` | 批量披露本回合 → 对方 turnStart（占点分→胜负检查） |
| `op{host}` | `{t:'op', k:'host', on:bool}` | 主动托管开关；任意合法 op 或 resume 即夺回 |
| `op{concede}` | `{t:'op', k:'concede'}` | 认负 → end{reason:'resign'} |

**下行（ruling 单通道 + end）**：

| 消息 | 字段 | 说明 |
|---|---|---|
| `ruling` | `{t:'ruling', frame, turn, seat, phase:'deploy'\|'act', timerMs, events:[…], state, quip?}` | 每 op 裁决 + 回合事件。events：`{k:'deploy',seat}\|{k:'reveal'}\|{k:'move',unit,seat,path}\|{k:'attack',unit,seat,tgt,dmg}\|{k:'counter',unit,tgt,dmg}\|{k:'skill',unit,seat,cell}\|{k:'heal',unit,tgt}\|{k:'die',unit,by}\|{k:'point',cell,owner}\|{k:'score',seat,pts}\|{k:'undo',seat}\|{k:'turn',seat}\|{k:'endTurn',seat}\|{k:'timeout-turn',seat}\|{k:'reject',why}` |
| `end` | 协议 §4.2 同形 | reason ∈ `wipe\|score\|timeout\|afk\|resign\|abandon`；scores={A:{pts,kills,value},B:…}；quip（§4.6）；终局附 reveal（部署史全披露） |

**state（canonical，服务器全量）**：`{turn, turnCounts:{0,1}, phase, ap:{seat}, undoUsed, units:[{id,seat,type,r,c,hp,phase,moveSteps}], terrain:[64], points:[cell,cell], owners:{cell:seat}, scores:{A,B}, deploys:{0:[…],1:[…]}, host:{0,1}, timerBase}`。

**个性化（personalize 钩子，element §5.3 先例——sim 声明、rooms 广播层逐连接换视图）**：

- **deploy 相位**：互见对方部署区为空（「未部署」），己方布置实时。
- **act 相位**：操作者收逐 op 实时 ruling（含全量 state）；**对手/观战收「已提交边界态」**（对手上一 endTurn 后的盘面）——对手整回合的动作在其 endTurn 才批量披露（§5.4）。
- 观战：deploy 双隐藏；act 恒边界态（每 endTurn 跳一格）。
- **确定性不受影响**：canonical 恒为服务器全量态（重放/双跑用 canonical），个性化只裁下发视图（element §5.3 同裁定）。

### 5.4 回合披露、悔棋与并发冲突裁决（单据指定三项）

- **对手回合批量披露（turn-commit）**：对手在你回合只看到边界态，其 endTurn 到达时一次性收全回合事件序列（客户端按 300ms/激活演出回放，§3.2）。三重收益：① 悔棋零信息泄漏（undo 回滚的是对手从未见过的世界）② 杜绝"盯着对方半回合临场反应"的不公平面 ③ 对手侧带宽降为 1 条/回合。代价（对手回合非逐 op 目击）由回放演出补偿——观战 feed 节奏同样成立（每 10-20s 一次完整回合演出）。
- **悔棋**：turnStart 时服务器深拷贝快照（64 格盘 + ≤12 单位，<2KB）；`undo` op 校验 {己方 act 相位 ∧ undoUsed=false} → 整体恢复（AP 回 4、单位激活态/位置/HP/死亡/据点翻转全回滚）→ ruling 附恢复后全量 state。≤1 次/回合；Bot 恒不用（§4.4）。
- **并发冲突裁决（串行单通道语义）**：房间 op 按到达序串行处理（Node 事件循环天然全序）；每条 op 处理前全量校验 {phase/回合归属/单位所有权/AP/激活态/路径与射程合法性}——不符回 `{k:'reject',why}` + 全量 state（客户端以回执为准自愈）。三类竞态逐一裁定：
  - **双击/重复提交**：第二条因激活态或占位校验 reject（幂等安全）；
  - **endTurn vs 回合超时**：超时判定挂 room tick 步进，与 op 到达在事件循环天然串行——先到者生效：endTurn 先到正常换手；tick 先到则该回合转 casual 代打完成（事件 `{k:'timeout-turn'}` 入账），随后到达的该席 op reject not-your-turn。账本保序 → 回放含托管代打段（决策固化，S1 范式）；
  - **undo 与在途 op 交错**：串行同理——undo 后到达的"撤销前意图 op"按恢复后态校验（多半 reject），语义正确。

### 5.5 seed 派生链与确定性红线（QA 核验口径）

- **派生链（冻结）**：`roomSeed = fnv1a32(roomId)`（测试房 §8.1 `seed` 钉死）→ `mapId = roomSeed % 4`（四图唯一随机位）→ Bot 决策流 `botSeed[seat] = mulberry32(roomSeed ^ (seat+1)·0x9E3779B9)`（casual 随机与 competitive 部署定桩共用，按决策事件序消费）。
- **零隐藏随机**：判定路径零随机（§5.1 表）；地图=房间级常数、部署超时=常量表、反击/火球=确定性规则——**随机只存在于 Bot 决策且服务端侧消耗**。
- **红线清单**：全整数态 ✓ 判定路径零随机 ✓ 结算序固定（§1.2/§1.4）✓ seed 派生链冻结 ✓ serialize 键字母序+数组固定序 ✓ 个性化视图不影响 canonical ✓ AOE/结算 tie-break 显式（unit id 升序）✓ 快照恢复=整体替换（无部分态残留）✓。

### 5.6 确定性与回放（重放 = 重放 op 日志）

- **输入日志**：`{seed, deploys:{0:[…],1:[…]}, ops:[{frame, seat, k, …payload}]}`（含系统事件 `timeout-turn` 段标记与默认阵代置标记）——回放器从 roomSeed 派生 mapId、按序重放 deploys+ops 即整局复算（托管 Bot 决策固化在日志，回放不重跑 Bot——S1 范式照搬）。终态 stateHash 与在线一致 = 确定性证明。
- **双跑剧本**（A6 断言）：同 seed 同 op 序列两房 → 终态 stateHash 与输入日志逐字节相等。
- 战报回放（结算页入口，V1-S1-06 采纳 §8）：输入日志重放逐步演示——与 QA 复验共用同一机制（slg §5.3 预留格式的消费）。

### 5.7 断线重连、席位与负载预算

- **重连**（协议 §2 的 10s+1 拍窗）：`join resume{seat,token}` → welcome **全量个性化 state 一次性恢复**——含 turn/phase/AP/各单位激活态/timerMs/undoUsed/占点分/托管标志/（act 相位则己方回合实时态、对手回合边界态）。恢复 <1s。
- **托管语义**：重连窗尽或主动托管 → §4.5 倾向继承 Bot 接管直至终局或回归；回合计时对断线方**不暂停**（超时单回合 casual 代打）；连续 3 全超时回合 afk 认负（连接在而不动——白嫖防线）；双方皆断线 15s abandon 收房。BotHost 纯 bot 房被真人接管时，部署期已交的布置继承（「棋局不等人」，element O-1 裁量先例照搬）。
- **带宽/端**：事件驱动——操作者 ~5-8 条 ruling（~1KB）/回合、对手 1 条批量（~2KB）、静默期趋零（仅心跳）——低于 element 逐 op 双播口径，全目录最低档。
- **网关负载**：无逐 tick 模拟（计时器外零计算）、裁决为小整数操作、Bot competitive <100ms/回合——单进程 50 房 STRESS 余量同 element §5.8 口径（QA/STRESS 单按此复核）。
- **房间**：seats=2、`teams:{A:[0],B:[1]}`；room tick=10ms、maxTicks=60000；waiting→live(deploy)→ended 沿用协议；终局 8s 展示窗；`end.scores` 含 pts/kills/value（战报与 quip 判据源）。

1. **S1+S5 结合形态：确定性引擎两端同跑 + 服务器回合权威**——S1 的战棋形态不是 lockstep 逐帧（回合制无逐帧输入），而是「同一份纯函数引擎（applyOp）两端可复算」：服务器权威裁决为唯一事实，客户端用同款引擎做选中/移动域/伤害预演（<100ms 手感全本地，S1 纪律表 §5.1 逐条落位）；确定性回放/双跑（A6）是 S1 深度要求的继承兑现。S5 面整层照搬 element（op/ruling、个性化、托管三层、afk 三分离、零快照流）——双技术复用 = 「S1 的芯 + S5 的壳」。
2. **行动点池（AP=4 < 编制 6）而非全员行动**——单据指定行动点制的具体化：每回合必有 2 单位不动，调度取舍是本作核心棋感；同时压住 Bot 组合空间（≤4 激活 × ≤720 单激活动作，贪心+2-ply 可解）与局时（回合 20-30s，一局 5-9 分钟）。
3. **对手回合批量披露（turn-commit）**——undo 零信息泄漏 + 杜绝半回合临场反应 + 对手带宽 1 条/回合；代价（非逐 op 目击）用 300ms/激活的回合回放演出补偿，观战 feed 节奏反而更"棋谱化"。悔棋因此可为：turnStart 快照整体恢复，≤1 次/回合。
4. **并发裁决 = 串行单通道 + 到达序全序账本**——双击幂等 reject、endTurn/超时竞态先到者生效、undo 与在途 op 按恢复后态校验；全部竞态在 Node 事件循环天然串行下有确定语义，账本（含 timeout-turn 系统事件）保序即回放完整。
5. **部署相位密置 + 揭示**——个性化视图（element §5.3 迷雾先例）的战棋用法：20s 双方密布 16 格部署区、双交或超时揭示；超时默认阵代置保确定性；编制镜像公平 + 布置自由 = 零平衡风险的"开局决策"。
6. **v1 无 LOS 遮挡**——山岩仅不可通行：8×8 + 曼哈顿射程 1-3 下遮挡规则收益（多一维站位）小于成本（整数视线判定 + 预览复杂度 + Bot 威胁图膨胀）；留弹性单。
7. **升级/装备不做**（§2.6 三条论证）——固定镜像编制保平衡全测性与回放状态封闭性；点将/装备留弹性位（编制表=sim 常量，换表即换 meta）。
8. **反击全强度、无追击、伤害下限 1**——反击承载"站位价值的一半"（bow 邻接不可反击的软肋、healer 反击 4 伤的鸡肋都是内容）；无追击防速度值膨胀；下限 1 保证任何单位永不零贡献。
9. **占点=占据翻转+持续持有，占点分通道先到 10**——slg 双通道（摧毁/积分）的回合制转译：满占双点 5 回合到线，逼中场接团；timeout 计分 = 占点分 + 存活价值（130/方），双保底封住"一局 5-10 分钟"。
10. **先手补偿 = 后手起始占点分 +1**——回合制先手优势的轻量补偿（element 后手 4 张先例）；数值面留 game.json 可调位，不引入规则面复杂度。
