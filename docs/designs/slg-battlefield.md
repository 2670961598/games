## 1. 玩法循环

**定位**：双人指挥官对战（2v2，席位不足 Bot 补位），宏观指挥型 SLG/RTS——玩家是"指挥官"而非单个单位：不直接操纵战斗，而是通过**出兵、技能、集结**三种指令驱动军团沿车道推进。S1 帧同步 lockstep 承载（roadmap 技术矩阵 S1 首证 SLG）。

### 1.1 地图与布局（375×667 竖屏，全局坐标系）

```
y=0    ┌──────────────────────────────┐ ─┐
       │  B 队基地（HP 1500）  row 0    │  │ 60px 顶栏（敌方基地血条/积分）
       │  B 防御塔（中车道 row 2）      │ ─┘
       │ 车道0(左125px)│车道1│车道2(右) │
       │  ▲信号塔Alpha（车道0 row 6）   │    战场 375×500
       │  ▼信号塔Bravo（车道2 row 13）  │    20 行×25px 格，15 列
       │  A 防御塔（中车道 row 17）     │
y=500  │  A 队基地（HP 1500）  row 19   │
       ├──────────────────────────────┤ ─┐
       │ 资源条│兵力条│6 张出兵卡│4 技能钮│  │ 107px 底部指挥区（单拇指）
       └──────────────────────────────┘ ─┘
```

- 队伍：`team = seat % 2`（A=偶数席在下方，向 y 减小方向进攻；B=奇数席在上方），与协议席位约定一致。
- 坐标：sim 用 milli-px 整数（见 §5.2）；本节及数值表用 px/格（row 0-19）便于读。
- 两座信号塔（占领点）对称分布（Alpha 在 A 视角 1/3 深度、Bravo 在 2/3 深度），双方到点距离相等——无先手不对称。

### 1.2 三循环（资源 → 出兵 → 技能）

| 循环 | 机制 | 数值 |
|---|---|---|
| 资源 | 指挥点 CP 自动增长，信号塔占领加速；开局 CP=40 | 基础 2 CP/s；每占 1 塔 +1 CP/s（满占 4 CP/s）；CP 上限 200 |
| 出兵 | 花 CP 从基地造兵，指定车道推进；在场兵力上限约束 | 上限 12 单位/玩家（pop）；出兵卡按当前基地阶（T1/T2/T3）取数值表 |
| 技能 | 能量条（击杀/占点/时间积攒）释放指挥官技能 | 能量上限 100；获取：击杀 +⌈敌兵造价/10⌉（inf +2 … heavy +11）、占点完成 +15、自然 +1/s |

**基地升级（第四隐藏循环——研究）**：花 CP 升级基地阶 T1→T2（150 CP，30s 研发）→T3（300 CP，45s）。基地阶决定出兵卡数值档（在场旧兵保持出生时快照，不回溯强化）。研究期间出兵照常。

### 1.3 胜负条件（双通道，先到者胜）

1. **摧毁**：敌方基地 HP 归零（基地 1500 HP，防御塔 500 HP 是最后一道防线）→ reason=`eliminated`。
2. **占领积分**：每守信号塔每秒 +2 分，先到 **400 分** 胜（满占 2 塔理论最快 100s，实战有争夺）→ reason=`score`。
3. **超时**：maxTicks=2700（4.5 分钟）→ 按**积分**高者胜，平则比基地 HP 百分比，再平 `draw` → reason=`timeout`。
4. abandon（全员离线 15s）沿用协议。

预期对局长 2.5-4 分钟（3-5 分钟区间内）：快攻流 2.5-3 分钟（摧毁）、运营流 3-4 分钟（T3 兵推或积分）、龟缩流被积分逼出战（100s 满占倒计时压迫感）。

### 1.4 单拇指操作映射（375×667 安全区，右手拇指全程可达）

| 手势 | 指令 | 反馈 |
|---|---|---|
| **拖**（出兵卡 → 车道） | `spawn`：拇指按住出兵卡拖到目标车道松手 = 从基地沿该车道出兵（指挥路径即车道） | 卡牌跟手、车道高亮、松手落点涟漪 + 基地舱门动效 |
| **点**（技能钮） | `skill`：点技能钮进入瞄准态（车道高亮）再点车道释放；维修/号令类无瞄准直接释放 | 钮按下缩放、冷却环扫过、能量条扣减 |
| **长按**（战场 ≥400ms） | `rally`：设该车道集结线，后续该车道出兵以集结线为推进目标（再长按拖动可改；点基地图标重置） | 长按震动感（视觉脉冲）+ 集结旗标记 |
| 点（升级钮，底栏左端小钮） | `research`：基地升阶（资源不足时置灰） | 研究进度条 |

单拇指原则：所有指令落点都在底部 107px 指挥区 + 战场车道三分区（大目标，无需精确定位——200ms 延迟下不惩罚瞄准，见 §3.1）。战场滚动/缩放**无**——全局战场一屏尽收（宏观指挥型 RTS 的核心取舍）。

### 2.2 指挥官技能表（≤4，全部走 `skill` op）

| 技能 | 代码 | 能量 | 冷却 tick | 持续 | 效果 |
|---|---|---|---|---|---|
| 火力覆盖 | `barrage` | 60 | 200（20s） | 瞬发 | 指定 {lane,row} 半径 45px 区域，3 发炮击（命中帧为释放后第 0/2/4 tick），每发 40 伤害（AOE 全额，敌我不分——命中己方也掉血，谨慎使用） |
| 紧急维修 | `repair` | 40 | 250（25s） | 瞬发 | 己方基地 +250 HP（不超上限 1500）+ 全体在场友军 +50 HP |
| 空降突击 | `drop` | 70 | 300（30s） | 瞬发 | 3 个**当前阶** `inf` 空降至指定 {lane,row}（中心+前后各 1 格固定编队）；下落 15 tick（无敌，落地即可行动）；无视 pop 上限（超编部分阵亡后释放） |
| 集结号令 | `surge` | 50 | 240（24s） | 50 tick | 全体友军攻击间隔 ×2/3（Q8 定点 `interval*171>>8`，下限 4 tick），持续 5s |

技能释放瞄准：`barrage`/`drop` 需点目标车道+大致纵向位置（吸附到 row 整数）；`repair`/`surge` 全局效果直接释放。

## 3. 手感参数

### 3.1 输入 → 表现延迟预算（红线：<150ms 本地表现）

| 环节 | 预算 | 实现 |
|---|---|---|
| 出兵确认（本地乐观表现） | **≤16ms（1 帧）** | 拇指松手即刻：卡牌扣 CP 显示、兵力条 +1、基地舱门动效启动——不等权威帧（lockstep 下的即时手感来源） |
| 权威确认（单位实体入场） | ≤3 tick（300ms @200ms 模拟延迟） | 输入帧 F+1（input delay=1）→ sim 生成单位 → `frame.events` 出 `{k:'spawn'}` 回流；RTS 宏观节奏下 300ms 单位入场无感（非格斗/射击的逐帧判定） |
| 技能反馈 | 释放即特效（本地），伤害判定随权威帧 | barrage 弹道动画 4 tick 与 sim 命中帧对齐 |
| 回滚 | 不回滚（S1 lockstep 无预测回滚） | 乐观表现仅限"卡牌扣费/队列数字"这类可由权威帧纠正的软状态（CP 不足时权威帧拒绝 → 卡牌抖动红闪 1 次 + CP 数字回弹） |

单局输入频率估算：出兵 1 次/2-4s + 技能偶发——远低于 lockstep 带宽瓶颈；每帧输入为单 cmd 或 noop，帧体积极小（§5.1）。

### 3.2 出兵反馈动效（juice 清单）

卡牌按压缩放（0.92× 弹回 120ms）→ 拖动时目标车道地面高亮呼吸 → 松手：落点涟漪 200ms + 基地舱门开合 200ms + 新单位从舱门"涌出"（前 200ms 尺度 0.6→1.0）+ 对应车道兵力条 +1 跳动。CP 数字滚动（-20 飘字）。

### 3.3 击杀 juice

- 单位阵亡：部件碎裂粒子（300ms，阵营色）+ 命中火花；`{k:'die'}` 事件驱动（客户端零 diff 触发，协议 §5 事件流）。
- 击杀方积分飘字（+2 能量飘字在 killer 指挥官 HUD）。
- 连杀节奏：同一指挥官 5s 内 3+ 击杀 → 屏幕下方 "连续歼击 ×3" 弹跳横幅 + 音效升调。
- 基地受击：全屏边缘红/青脉冲（受击方视角）+ 基地裂纹渐进（75%/50%/25% 三档贴图）。
- 基地摧毁：慢动作 0.5×（渲染层 timeScale，模拟不变）2s + 大爆炸粒子 + 震屏（渲染层 shake ±6px 衰减 500ms）。
- 音效锚点：出兵（低音步号）/命中（短脆）/阵亡（闷响）/技能（技能各异）/终局（胜利号角|失败低音）。

## 4. 难度曲线（Bot 三档策略）

Bot 走网关 Bot 宿主统一接口（`spawnBot('slg-battlefield', level)`，brain 逐帧生成输入走输入通道，协议 §5）。三档参数表（可执行，DEV 抄进 sim 文件头）：

| 参数 | casual 休闲 | balanced 均衡 | competitive 竞技 |
|---|---|---|---|
| 首行动 tick | 150（开局挂机 15s） | 30 | 8 |
| 决策间隔 | 50 tick | 20 tick | 10 tick |
| CP 使用 | 攒到 min(2×造价, 199CP) 才出兵（F1：闸门不得超 CP 上限） | 攒到 1× 即出 | 克制储蓄：目标克制兵攒够才出，300 tick 窗口封顶、超窗降级 inf（F2：替代"有 CP 即花"） |
| 兵种选择 | 解锁池内 rng 均匀 | 固定轮换 inf→razor→arty | **克制表**：敌方最近 3 次出兵众数 → 出克制兵（inf↔razor↔arty 三角、多 sniper→razor、多 heavy→arty）；敌无情报→按己方科技阶最优性价比 |
| 开局节奏 | 无（观察） | 2×inf 试探（tick 30/50） | 快攻：前 30s 连续 3×inf 同车道 + tick 25 `drop` 抢中路压制 |
| 车道选择 | rng | 两车道轮换 | 最弱点：敌方兵力最薄的车道（按可见兵力计数）；敌迫己方基地 5 行内 → 直援该道（F2 保命压顶） |
| 信号塔 | 不占 | 路过顺占（≥2 单位经过时） | 专职：tick 40 前派 1×inf 占最近塔；点被夺 10s 内反攻；未持有的塔持续争——点上己方 <2 时续送上点（F2，攒局部 2v1 防添油） |
| 技能使用 | 有能量+冷却好 30% 概率随机放（barrage 常放空） | barrage：敌集群 ≥4 或敌推塔时；repair：基地 <60% | barrage：敌集群 ≥4 **或敌方 surge 期间**；drop：抢点/断兵线；surge：己方 ≥6 单位推家时；repair：基地 <75% 即用 |
| 研究 | 从不 | tick 600 起 T2 | tick 400 起 T2（敌众数非 inf 时储蓄让位克制出兵）；T3 机会式：攒够即升不硬储蓄（F2） |
| 集结 | 无 | 前线 1/2 深度 | 有未持有塔 → 该塔车道集结塔位；双塔在手 → 动态随战团位置 |

难度曲线设计意图：casual 给新手"能推平"的正反馈（A2 剧本）；balanced 是陪玩主力（有来有回但决策慢半拍）；competitive 提供速通压力测试与竞技体验（A3 剧本：tick 8 首兵 + 快攻 3 分钟内拆掉挂机玩家）。真人加入让位/掉线托管沿用协议 §2（casual 档托管断线真人，体验友好）。

> **FIX 记录（GAMES-45 · 2026-09-27）**：QA 一号（GAMES-44）发现两处参数级玩法缺陷，本单修正并实测：
> **F1（casual heavy 死锁）** 攒钱闸门原为字面 2×造价，heavy 2×110=220 > CP 上限 200 永不可达，且 wanted 只在成功出兵后重掷 → casual 掷中 heavy 即整局零出兵、CP 顶死（复现：seed=20260977 混合席 seat2 spawned=0）。修复：闸门夹取 min(2×cost, CP_MAX−1CP)。
> **F2（三档无梯度/克制表不可达）** competitive"有 CP 即花"与克制表互锁（2CP/s 收入下 45/70CP 克制兵永攒不齐，QA 5 局 0 次非 inf 出兵），信号塔反攻仅覆盖"持有后被夺"（从未持有则永久弃塔，让出积分通道被 score 推平）。修复五件套：① 克制储蓄窗口（300 tick 封顶、超窗降级 inf、出兵即重开——即"支付档降级"）；② 未持有塔持续争塔（<2 续送，防添油）；③ 保命压顶（敌迫基地 5 行内车道直援）；④ T2 储蓄遇克制情报（敌众数非 inf）让位出兵；⑤ T3 改机会式升阶（300CP 硬储蓄≈后半局弃权）。
> 修复后实测（vs macro-push 参考策略，每档 3 局）：casual 0/3（被拆@724-1005）、balanced 0/3（score 负@1240）、competitive **3/3 胜**（score 胜@1370）——胜率梯度成立；razor 铺场探针从 ~711 tick 被单方面推平 → 2180 tick 积分 400:386 憾负、基地保全、克制兵（arty/razor）正常上场。上表为修正后行为；§6 剧本与断言不变（A2/A3 复验绿）。

> **BOT 深化记录（GAMES-46 · 2026-09-27）**：在 F1/F2 底座上叠**人格层**——Bot 是内容不是填充（制作人指令）。行为事实源=sim.cjs brain 段头"三档人格"注释+行为清单；要点：
> **① 三档人格化差异**：casual=慢节奏陪玩（走神窗口 15%/1.2-2s 明显失误留窗、基地被打 5s 内 60% 概率回敬 1×inf 的温和回击）；balanced=标准节奏（原样）；competitive=快开+克制针对（F2 底座）+**集火残血**（barrage 目标评分=集群数+2×残血数（hp≤40%），残血≥2 即使集群<4 也打）+**守塔换位**（持有塔 2.5 行内出现敌军→出兵道让位协防+集结线收到塔位，优先级：保命压顶>守塔>争塔>最弱点）。
> **② 陪玩模式**（casual 房）：同队有真人（网关经 brain 第 5 参 env.kinds 透传名册；离线端 seat0=真人同口径）的 casual bot"带躺不抢戏"——真人活跃（spawned/kills/tier/research/rally 快照在变）→ 让位：3× 出兵闸门+pop≤4+集结钉己方 1/3 守势线+barrage/surge 全让（维修仅基地<40% 保命）；真人静默>150 tick（carry.idleTicks）→ 接管节奏：恢复正常 casual 行为+集结线顶到中线（真人回线自动让回）。
> **③ 猎杀让力**（competitive 房，game.json `net.botTuning.mercy` 可调）：己队分差≥triggerGap(150) → 整档收力至 balanced 水平（决策间隔 20 tick/技能收敛/无 drop 断线/研究降档），回落≤releaseGap(75) 才恢复（滞回防抖）——纯分差函数，确定性不破，触发区间可由分差时间线精确重构。
> **④ 开局树**：三档各 2 套，开局由服务端 botRng（房间 seed 派生）在首决策 tick 一次性定桩——同 seed 同局必同树。casual：C0 懒散混编｜C1 慢热占塔（首兵 inf 走最近塔道+一次性塔位集结）；balanced：B0 中路试探（inf 起手、左道起）｜B1 双线占塔（razor 起手、右道起、开局即双塔道集结）；competitive：P0 快攻抢塔（原版）｜P1 中路压制（3×inf 直推中路、无开局 rally、drop 前期只断兵线）。
> **⑤ 调参面**：`net.botTuning = { mercy:{triggerGap,releaseGap,level}, carry:{idleTicks} }`——game.json 为可调事实源，服务端适配器启动时注入 sim（sim 内置同值默认兜底离线端）。§6 剧本与断言不变（A2/A3 复验绿；A3 观感从"单方面拆家"变为让力后 400:284 积分收官，胜方不变）。

## 5. S1 帧同步协议细节

本节在 net-protocol.md v1.1 冻结框架内落 slg-battlefield 的实现细则；**不新增消息类型**（复用 §4.1 `input`/§4.2 `frame`/`state` 等），故无需协议变更单。

### 5.1 指令粒度与输入编码（tick=100ms 输入帧）

- 定频：`tickMs=100`（协议 §5 同 net-tank）；帧 `F` 携带第 F 帧全席位输入。
- **RTS 指令是离散事件**（非 net-tank 的持续向量）：每席位每帧至多 1 条 cmd，无指令发 `noop`。客户端连续快速操作时本地排队，逐帧各发 1 条（出兵卡冷却 2 tick 天然限速，队列不积压）。
- 输入编码（`input` 消息 `keys` 壳内，游戏自定义键集——协议 §8.3 `ops.keys` 游戏级声明）：

```
input = { t:'input', frame:F+1, keys:{ cmd:{…} } }
cmd ∈
  {k:'spawn',   unit:'inf'|'razor'|'arty'|'sniper'|'medic'|'heavy', lane:0|1|2}
  {k:'skill',   id:0|1|2|3, lane?:0|1|2, row?:0..19}   // id 见 §2.2；barrage/drop 需 lane+row
  {k:'rally',   lane:0|1|2, row:0..19}
  {k:'research',tier:2|3}
  {k:'noop'}
```

- 全部字段整数/枚举，无浮点、无字符串拼接解析歧义；`noop` 帧与"未收到输入沿用上帧"（§5.4 宽限）在 sim 内等价——**RTS 下沿用=静默，天然无卡死风险**。
- `frame.events`（下行，客户端零 diff 触发特效）：`{k:'spawn',seat,unit,lane}` / `{k:'die',seat,by,unit}` / `{k:'hit',seat,by,dmg}`（聚合每帧每受击者一条）/ `{k:'skill',seat,id,lane,row}` / `{k:'cap',tower,alpha:0..100,owner}` / `{k:'research',seat,tier,done:0|1}` / `{k:'basehp',seat,hp}`。

### 5.2 确定性规则（红线，QA 按此核验）

1. **全整数模拟**：位置 milli-px（int32）；速度 milli-px/tick；HP/伤害/造价整型；CP 与积分用 milli 单位整型（CP 上限 200 = 200_000 milli）。每 tick 推进只有整数运算：`+ - * Math.imul >>`，除法一律 `(a/b)|0` 向零取整；无 `Math.random`、无 `Date.now`、无浮点字面量进 sim 路径。
2. **Q8.8 定点乘子**：克制/技能/攻速乘数全部定点（×1.5=384，×1.75=448，×2/3=171，×2=512），伤害计算 `dmg = base*multQ8>>8`。
3. **移动模型**：车道制 1D——单位绑定 {lane, dir, y}，每 tick `y += dir * spdMilli`；**无 A\*、无碰撞解算**（车道即路径，指挥的"路径"语义由车道选择承载）。横向视觉散布是渲染层的事（按 unit id 确定性偏移，不入模拟）。
4. **索敌与 tie-break（全序）**：射程判定 `dist2 = (Δlane*125_000)² + (Δy)²`（milli-px 平方，int32 安全：125_000²≈1.56e10 需 imul 中间量——实现用 `Math.imul(ΔlaneMilli, ΔlaneMilli)` 后相加，JS 整数 ±2^53 内精确）；候选按 `(dist2, entityId)` 字典序取最小——**任何排序比较器都必须是全序**（dist2 相同以 id 破平），禁用非稳定排序。
5. **AOE/遍历序**：范围伤害按 entityId 升序遍历结算（结算顺序影响 HP 归零与 by 归属，必须固定）。
6. **随机**：**sim 本体零随机**——地图固定对称布局（§1.1）、空降编队固定、AOE 无散布。随机只存在于 Bot 决策（brain 的 rng 参数，**服务端侧消耗**，其结果已固化为输入帧下发，客户端只回放输入——不破坏客户端确定性）；客户端装饰随机（粒子/涟漪）不进判定。`seed = fnv1a32(roomId)` 仍按协议计算并随 welcome 下发、sim 记录在 state（预留演出层用途，判定路径不消耗）。
7. **同 tick 确定性结算序**：`research → spawn/drop 落地 → 移动 → 医疗光环 → 普攻/AOE（按攻击者 id 升序） → barrage 落弹 → 占点 → 能量/CP/积分结算 → 胜负判定`。每局固定不变。
8. **serialize/deserialize**：state 与 JSON 的字段序固定（键按字母序序列化），供快照/回放 hash 比对。

### 5.3 断线重连与快照

- **服务端权威**：网关逐步跑同一份 sim（裁判+Bot 依据），终局以服务端判定为准（协议 §5）；客户端模拟仅呈现。
- **关键帧快照**：服务端每 30 tick（3s）serialize 全量 state（含 fnv1a32(state JSON) 校验 hash），环形缓冲 20 份（覆盖 60s）；输入日志自最近关键帧起全保留。
- **重连路径**（协议 §2 的 10s 窗）：`join resume{seat,token}` → 服务端回 `welcome`（全量当前 state，非快照+log——slg state 小，全量最简）→ 客户端 rAF 追帧（每帧模拟 2-4 tick 渲染 1 帧）至当前帧恢复实时。逾时席位转 bot 托管（casual 档），续看至终局。
- **`sync` 纠偏**：客户端检测帧缺失/校验不符即发 `sync`，服务端回全量 `state`（协议 §4.2）。
- **确定性回放**（roadmap S1 深度要求"展示确定性回放"）：终局输入日志归档 = `{seed, tickMs, inputs[frame]→cmd}`；回放器从 frame 0 重建整局，终态 hash 与服务端一致即为确定性证明——QA 复验与结算页"战报回放"共用此机制（回放功能排 VIS 单链 #9，本设计预留格式）。

### 5.4 最慢者定帧与输入延迟缓冲

- 沿用协议 §5：**input delay=1**（收到帧 F 后立刻上报 F+1 输入）+ **40ms 输入宽限**（到点未收到的真人席位沿用上帧输入——本作语义即 noop，安全）。
- **200ms 模拟延迟可玩性论证**：指令链路 = 本地乐观表现 0ms（§3.1）+ 帧确认 ≤3 tick；宏观 RTS 无逐帧走位判定，玩家感知为"出兵指令即时、军团入场稍慢半拍"，属策略游戏自然节奏。测试口径：api-check A4（注入→帧反映 <100ms，服务端同钟）+ QA 二号单 tc 200ms 模拟延迟试玩。
- 追帧上限：重连/卡顿恢复后每 rAF 至多模拟 4 tick（net-tank 同款），防螺旋卡死。

## 附：设计决策记录（REPORT 引用）

1. **车道制 1D 移动，不做自由寻路**——竖屏单拇指 + tick 100ms + 确定性三条约束下，A*/碰撞解算是确定性与性能的双重风险源；车道承载"指挥路径"语义，指挥深度保留在兵种克制/时机/资源曲线。roadmap S1 的深度要求（输入延迟/定帧/确定性回放）全部不受影响。
2. **离散 cmd 输入而非持续向量**——RTS 指令天然低频离散；沿协议 input 消息的 keys 壳扩展游戏键集（§8.3 游戏级声明），零协议变更。
3. **sim 本体零随机**——比"seed 驱动一切随机"更强的确定性主张：判定路径连 seed 都不消耗，Bot 随机全在服务端侧且固化为输入。回放=纯输入序列重放。
4. **双胜负通道（摧毁/积分）**——单通道摧毁会奖励龟缩 T3 载具流拖满 4.5 分钟；积分通道制造 100s 满占倒计时，强制接团，对局锁定 2.5-4 分钟。
5. **乐观表现不回滚**——S1 无预测回滚（那是 S7 的活）；出兵确认的即时感来自本地软状态（卡牌/数字），权威帧 300ms 内到场纠正，200ms 延迟预算内自洽。
6. **超编 drop 无视 pop**——空降的战术价值（抢点/断线）不该被 12 上限抹平；超编部分阵亡即释放，无永久泄漏。
