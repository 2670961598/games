## 1. 玩法循环

**定位**：桌面上的一局几何对弈——双人（Bot 补位轮流制）八球台球，**击球输入上传、服务端确定性物理模拟、状态同步下发**（roadmap 技术矩阵 S4 首证：服务器物理权威 + 确定性物理）。瞄准是脑、杆法是手、走位是势：一杆好球 = 精度 + 力度 + 旋转 + 下一杆的位置感。竖屏 375×667，桌面横置全览（无镜头滚动）。

### 1.1 对局时间轴（3-8 分钟，room tick=10ms，maxTicks=48000）

```
开赛 ── 破球 ── 定色 ── 清色 ── 黑八收官 ── 超时硬顶
  │  第1杆   │ 1-2min  │  2-4min  │  30s-1min │  8min
  │  全阵冲散  │ 首次合法落袋分色 │ 各清 7 球   │  合法打进黑八 │  剩球裁定
  回合制：aim(30s 计时) → motion(球动至全停) → resolve(规则结算) → 循环
```

- **破球**：第 1 杆从开球线后（x ≤ 85000）全阵冲击；破球落袋即定色（简化口径，见 §1.3）。
- **定色期**：开放球局（openTable）直到第一颗目标球落袋——落袋球类型（全色 1-7 / 花色 9-15）即归击球方，另一方自动归另一组。
- **清色期**：主循环——打进己组球续杆，失手/犯规换人；白球位置即下一杆的"势"。
- **黑八收官**：清完 7 颗后打 8 号：合法进 = 胜；早进/打 8 时白球落袋 = 负。
- **回合预算**：正常局 8-25 杆；每杆人类耗时 5-25s（aim 计时 30s）+ 球动 1.5-6s（§2.3 校核）→ 3-8 分钟。

### 1.2 回合状态机（服务器权威裁决，S5 语义承载于 S4 之上）

```
aim ──shot op──▶ motion ──全停/超帽──▶ resolve ──ruling──▶ aim（续杆或换人）
 │                │                      │
 │ 30s 超时        │ 硬帽 5000 子步        │ 黑八条件 ──▶ ended（end 消息）
 ▼                ▼ 强制全停              ▼
 timeout-shot    （防无限，预期不触发）    ball-in-hand（犯规后 aim 前置 place op）
（casual 随手杆代打；连续 3 次 → afk 认负）
```

- **aim**：仅当前回合席位可操作；瞄准/力度/旋转全部本地计算零上行（§5.6 延迟论证的根），commit 时一条 `shot` op 上行。
- **motion**：服务端跑 §2 确定性物理至全停（每球速度归零）；期间 10Hz 快照下发（§5.2）。
- **resolve**：服务端按 §1.3 规则结算（落袋/犯规/定色/续杆换人/胜负），`ruling` 下发。
- **ball-in-hand**：犯规后获球权方可任意放置白球（`place` op，服务端校验合法性）。

### 1.3 八球规则子集（分色 / 犯规 / 胜负——v1 有意收窄，先例：roadmap §4.1 D 单"规则子集"口径）

**分色**：开放球局首次目标球落袋即定色（含破球杆——简化：WPA 规则破球落袋不定色，本作省略该分支）；同杆双类型落袋按落袋顺序第一颗定色。定色后不可变。

**犯规（4 条，均判对方 ball-in-hand）**：

| # | 犯规 | 判据（sim 事实，§2.6 记录） |
|---|---|---|
| F1 | 白球落袋（scratch） | motion 期 id=0 进袋 |
| F2 | 空杆 | 白球全程未接触任何球（firstHit=null） |
| F3 | 首触错组 | 定色后白球首触非己组球（己组清完后首触非 8 号同罪；开放局首触 8 号同罪） |
| F4 | 无库无进 | 首触后无任何球碰库边且无任何球落袋 |

**胜负（先到者胜，reason 入 end 消息）**：

1. `eight-ball`：己组 7 球全清后**本杆开打前已清空**且 8 号合法落袋（白球未落、无犯规）→ 胜。
2. `early-eight`：8 号提前落袋，或打 8 杆白球同落 → 立即负（对方胜）。**例外**：破球杆 8 号落袋 = 8 号重置于置球点（foot spot；若被占沿 x−15100 步进至空位——确定性重置）继续比赛，不判负。
3. `timeout`：maxTicks=48000 → **剩球少者胜**（己组剩余数小者；开放局比总剩球；相等 draw）。
4. `afk`：连续 3 次 30s 超时 → 认负。`resign`：concede op 认负。`abandon` 沿用协议（全员离线 15s）。

**v1 不做**（规则子集外的有意放弃，FEEL/弹性单再议）：杆法喊球（no call shot）、跳球、库边球（F4 已覆盖其精神）、破球特殊换人规则、三犯判负。

### 1.4 三段操作映射（单拇指，375×667 安全区，右手全程可达）

| 段 | 手势 | 区位 | 说明 |
|---|---|---|---|
| ① 瞄准 | 桌面任意处 drag | 桌面全区（y 250-420） | 瞄准线 = 白球中心 → 手指方向；手指离白球越远角分辨率越精（高尔夫游戏惯技），量化 0.044°（§2.2） |
| ② 力度 | 右缘竖槽 drag | x 346-366, y 300-560 | 竖向力度槽 0-100%，拖动带 0.6 阻尼精调；杆尾拉杆动画镜像距离 |
| ③ 旋转 | 旋转盘 tap | 底栏左 44×44 九宫 | 中心/上下/左右/四角 → spinV（高低杆）× spinS（左右塞）九态（§2.5）；当前点高亮 |

## 2. 物理与数值表（定点方案——禁浮点，DEV 可直接抄 sim）

### 2.1 坐标、单位与子步（确定性三件套：整数态 / 固定子步 / 固定迭代）

- **坐标系**：桌面局部系（渲染偏移是客户端的事）：库边内沿 x∈[0,340000]、y∈[0,170000]（milli-px int32，340×170 逻辑 px，2:1 横置）。球心活动界 x∈[7500,332500]、y∈[7500,162500]。
- **球**：16 颗（0=白球，1-15），半径 r=7500 milli（7.5px；球/桌宽比 4.4%，实况 2.25%，放大求手机可瞄性）。等质量质点圆盘。
- **单位**：位置 milli-px（int32）；速度 **milli-px/子步**（int32）——子步是速度的隐含时间基，改子步率=改物理语义，冻结如下。
- **时钟**：房间 tick=10ms（100Hz，计时/快照/frame 号，与其他游戏同口径）；**每 tick 固定 S=5 个物理子步（子步=2ms，500Hz）**。motion 期服务端逐子步积分；全停期零物理开销（空闲房不烧 CPU，STRESS 口径 §5.6）。
- **反隧道证明**：最大杆速 Vmax=2800 milli/子步（1400px/s，§2.3 力度上限）；最大相向闭合 5600 milli/子步 < 检测窗 15000 milli（两球心和 ≤ 2r）——任一穿越必在某个子步边界落在 (8000,15000] 区间内被检出，**2.7× 安全余量，无需 CCD**。
- **算术纪律**（slg §5.2 第 1/2 条继承+加强）：sim 路径只允许 `+ − ×(操作数均为整数、|积|<2^53 精确) >> |(a/b)|0`；**禁 `Math.*` 一切函数**（三角用 §2.2 烘焙表，开方用二分 15 轮整数 isqrt）；除法一律向零取整；每步结算序固定（§2.6）。Q16.16 定点乘子：乘 `a*Q>>16`，全部烘焙常量。

### 2.2 三角与瞄准量化（精度即协议）

- **角度上传**：`ang` uint16 brads（65536/圈，0=+x 方向，顺时针为正——屏幕系 y 向下）。
- **量化**：入 sim 前统一右移 `q = ang >> 3`（8192 档/圈=0.044°/档；客户端 UI 即按此栅格吸附，服务端 sanitize 同式取整）。340000 milli 桌长下的最远端横向误差 = 340000×tan(0.022°) ≈ **130 milli（0.13px）**——对比球半径 7500，精度冗余 57×。
- **烘焙三角表**：`TRIG16`——四分之一正弦波 2048 项 Q16.16 int32（entry i = round(sin(π/2·i/2048)·65536)），连同余弦镜像与反正切表 `ATAN8`（2048 项，brads）由生成脚本一次性产出**并提交为源码常量**（determinism by construction：两端字节一致，不依赖运行时 Math）。DEV 交付物含 `scripts/gen-trig16.mjs` 与生成产物；sim 引用常量，红线不破。
- 方向取值：quadrant=q>>11，idx=q&2047 → cosQ/sinQ 查表（象限折叠）；速度分量 `vx=(V0*cosQ)>>16`、`vy=(V0*sinQ)>>16`，误差 ≤0.03 milli。

### 2.3 力度与摩擦（数值校核留档）

| 参数 | 常量 | 值 | 说明 |
|---|---|---|---|
| 力度上传 | pow | 0..1000 整数 | 千分力度 |
| 起杆速度 | V0 | `(pow*183501)>>16` milli/子步 | pow=1000→2800（1400px/s 破球杆）；500→1400（700px/s 中杆）；250→700（350px/s 轻杆） |
| 滑滚摩擦（乘性） | MU | 65369（0.997452/子步） | 速度² > VSLIP² 时每子步 `v=(v*MU)>>16`（速度比例衰减——滑动+快滚相，决定"距离∝初速"的手感） |
| 蠕动摩擦（减性） | −1 milli/子步 | 速度² ≤ VSLIP² 时各分量 `v-=sign(v)`（到 0 止） | 慢滚收尾：整数可表达的最小减速度，专治"指数长尾永不停" |
| 相变阈值 | VSLIP | 120 milli/子步（60px/s） | 两相分界（按速度²=14400 比较，无开方） |
| motion 硬帽 | CAP | 5000 子步（10s） | 到帽强制全停（确定性防无限，预期不触发） |

**两相摩擦的理由**：纯乘性指数永不停（需硬截断阈值，慢球会"匀速爬行"）；而 2ms 子步上任何 ≥1 milli 的常减速度换算 ≥250px/s²，会把中速球 0.3s 内杀停——整数粒度下"每子步减 12"这类单相混合式不可用（收尾计算留档：12 milli/子步²=3000px/s²，实况台呢滚阻 ~0.25m/s²≈38px/s²）。两相制让乘性相管距离、减性相管收尾，各自落在整数可表达且手感正确的区间。

**校核**（快相几何级数：距离 ≈ (V0−VSLIP)/(1−μ)，时长 = ln(V0/VSLIP)/0.002551 子步；慢相尾 ≤120 子步≈0.24s/7px）：

| 杆法 | V0（milli/子步） | 滚动距离 | 滚动时长 | 手感目标 |
|---|---|---|---|---|
| 轻杆 pow=250 | 700（350px/s） | ≈228px（0.67 桌长） | ≈1.4s（快相 1.11s+尾 0.24s） | 短距走位/安全球 |
| 中杆 pow=500 | 1400（700px/s） | ≈502px（1.5 桌长） | ≈2.2s（快相 1.93s+尾） | 常规进球杆 |
| 破球 pow=1000 | 2800（1400px/s） | ≈1052px（3.1 桌长，单球理论） | ≈2.7s（快相 2.47s+尾） | 全阵冲散；加碰撞/库边损耗 16 球全停 4-6s |

分速率校验：μ=0.997452/子步 → 每秒速度保留 ≈0.28。**观球时长带宽**：轻/中杆 1.4-2.2s、破球全停 4-6s——休闲节奏（实况台球量级的紧缩版，压进 3-8 分钟局预算），CAP=10s 兜底。

### 2.4 碰撞解算（迭代次数固定——红线）

**球-球弹性碰撞（等质量）**，每子步 **固定 2 轮** pairwise 解算，对序恒为 `(i,j)` id 字典序升序：

```
for pass in 1..2:                       # 迭代次数固定（红线）
  for i in 0..15, j in i+1..15:         # 全序遍历，禁排序
    dx=x[j]-x[i]; dy=y[j]-y[i]; d2=dx*dx+dy*dy        # ≤9e8，精确
    if d2==0 or d2>=15000²: continue                   # 2r=15000
    d=isqrt(d2)                                        # 二分 15 轮整数开方（确定性）
    nxQ=(dx<<16)/d; nyQ=(dy<<16)/d                     # Q16.16 法向（向零截断）
    vrel=((vx[i]-vx[j])*nxQ+(vy[i]-vy[j])*nyQ)>>16     # 法向相对速度
    if vrel>0:                                         # 仅在接近时解算（防粘连）
      jimp=(vrel*64225)>>16                            # (1+e)/2=0.98，e_ball=0.96
      vx[i]-=(jimp*nxQ)>>16; vx[j]+=(jimp*nxQ)>>16     # y 同式
    ov=15000-d; h=(ov>>1)                              # 位置分离（各半，向零截断）
    x[i]-=(h*nxQ)>>16; x[j]+=(h*nxQ)>>16               # y 同式；残余 ≤1 milli 由下子步再解
```

动量校核：正碰 vrel=V → 目标球得 0.98V、白球余 0.02V（近全传递 ✓）；e=0.96 的能量损耗落在 2% 法向冲量与摩擦。

**库边反弹**（袋口外区域，轴对齐四库）：

```
顶库：y<7500 且不在袋口区 → y=15000-y; vy=-(vy*53740)>>16; vx=(vx*58982)>>16
（e_cushion=0.82 法向 / 0.90 切向；其余三库对称；袋口区判定见 §2.5）
```

**袋口区**：库边线段在袋心沿线方向 CUT 范围内不设库（球可越线入颌）：角袋 CUT=13000、中袋 CUT=12500（袋口宽 26000/25000 milli ≈ 1.7-2.2× 球径，实况量级）。

**解算次序（每子步固定，不可换序）**：`① 积分 x+=vx,y+=vy → ② 球-球 ×2 轮 → ③ 库边反射（id 升序）→ ④ 袋检测/强制袋 → ⑤ 两相摩擦衰减（快相乘性/慢相减性，§2.3）→ ⑥ 全停判定`。

### 2.6 motion 事实记录（resolve 的判据源，确定性产生）

sim 在 motion 期顺带记录（不入物理，纯账本）：`firstHit`（白球首触球 id——首例白球参与且 vrel>0 的球-球解算）、`anyCushionAfter`（首触后任意球碰库标志）、`potted[]`（落袋顺序）、`cuePotted`、`subSteps` 计数。resolve 按 §1.3 规则消费。

## 4. Bot 三档策略（物理 Bot：几何解析瞄准 + 采样前瞻双轨）

Bot 走网关 Bot 宿主统一接口（`spawnBot('pool-physics', level)`），输出与真人完全相同的 `shot/place/concede` op（服务器权威校验，零特例通道）。**物理 Bot 是新领域**：瞄准不是格子选点而是连续角域解算——本节给可执行方案。Bot 算术同守 §2.1 整数纪律（TRIG16/ATAN8 查表；rng=mulberry32(seed^shotNo<<16^seat)，seed=fnv1a32(roomId)——同 seed 同决策，双跑剧本依赖此性质）。

### 4.1 共用几何解算核（ghost ball 反射几何——balanced/competitive 共用）

```
候选 = 己组活球 b（开放局=全体 1-15）× 6 袋 p：
  dir_bp = 单位(b→p)（ATAN8/三角表整数实现）
  ghost  = b − dir_bp×15000                    # 幽灵球位：白球心撞击点
  ang    = atan2(ghost−cue)                     # 瞄准角（brads）
  通路检查：cue→ghost 线段每 7500 milli 采样，任一他球距 <15000 → 堵死；
            b→p 线段同式（袋前遮挡）。
  切角可行性：cos_cut = dot(unit(cue→ghost), dir_bp) ≥ 16384（≤75°）；
  静态评分 = cos_cut²/2²⁰ − dist(cue,ghost)/2²⁰ − dist(b,p)/2¹⁹   # 切角主导、路程次之
  力度启发 = clamp(250 + (dist_cg+dist_bp/cos_cut)×3/2¹², 150, 900)（整数）
```

### 4.2 三档参数表

| 参数 | casual 随手杆 | balanced 几何瞄准 | competitive 走位规划 |
|---|---|---|---|
| 决策时机 | 轮到即打（0.5-1.5s 拟人延时） | 1-2s | 2-3s（前瞻在算） |
| 目标选择 | 候选池随机挑一（40% 直接瞄己组随机球心） | 静态评分最高者 | 静态 top-6 进前瞻 |
| 瞄准噪声 | ±2000 brads（±11°） | ±160 brads（±0.9°） | 前瞻内选优后 ±40 brads |
| 力度 | 随机 300-800 | 启发式 | 前瞻网格 {−10%, 启发, +10%} |
| 自旋 | 恒 0 | 恒 0 | 简单规则：长台直线杆低杆防跟进、贴库球高杆（两规则，整数判定） |
| 前瞻模拟 | 无 | 无 | **每候选 ≤2 变体 × ≤6 候选，硬帽 16 次**（§4.3） |
| 无进球候选时 | 朝最近合法球全力（常送对手机会） | 朝最近合法球中力 | **安全球**：合法球轻杆（pow 250）贴库留位 + 若可行把白球藏己组球后 |
| ball-in-hand | 随机合法位 | 网格 12×6 采样取静态评分最高位 | 同左 + 对每个候选位前瞻 1 次 |
| 破球杆 | 随机角 ±30° 全力 | 尖球正瞄 pow 1000 | 尖球偏 ±800 brads pow 1000 高杆（散球更开） |
| 预期进球率 | ~15-25% | ~55-70% | ~75-85% + 走位连续性 |

难度曲线意图：casual 给新手"能赢"的正反馈（乱枪常犯规送 ball-in-hand）；balanced 陪玩主力（几何准但无走位，局势会拉锯）；competitive 是黑八守门员（连杆终结 + 安全球折磨——A3 剧本压力源）。超时随手杆（§1.2）= casual 人格单杆（best 候选 + ±800 brads 噪声，pow 500）。

### 4.3 前瞻模拟（competitive 专属：服务端 scratch 副本合法）

Bot 在服务端把当前全量 state 克隆进 scratch 缓冲，用 **§2 同一份确定性引擎**跑候选杆法至全停（≤5000 子步），对终局打分：

```
score = +1000×己组落袋数 − 800×白球落袋 − 600×8号提前落袋
      + 下一杆质量（对终局局面跑 §4.1 静态评分最优值；无候选=−200）
      + 走位分（白球到下一目标平均距离的负值/2¹⁵）
```

预算硬帽：每次决策 ≤16 次前瞻 × 5000 子步（≈10⁷ 整数运算，JS <100ms），aim 期 30s 窗口内绰绰有余；STRESS 口径见 §5.6。**合法性**：Bot 与网关同进程读全量 state（slg"情报克制"先例——服务器侧读合法；对手客户端不可见 Bot 内部计算）。

## 5. S4 服务端权威物理协议细节（核心节）

本节在 net-protocol v1.1 冻结框架内落 pool-physics 实现细则；消息复用 §6 预留扩展位——**S4 行 `welcome.room.physics` 声明块 + `snapshot.ext.physics`、S5 行 `t:'op'`（上行）/`t:'ruling'`（下行）**——零新增消息类型、零协议变更（S3 帝国萌芽游戏级声明先例）。DEV 单随交付把 net-protocol.md §6 S4/S5 行从"预留"改注"已实证（pool-physics）"并回填 payload 规格（GAMES-74 O1 文档化先例）。

### 5.1 消息规格（JSON 文本帧）

**上行（op 通道，S5 预留位）**：

| 消息 | 字段 | 说明 |
|---|---|---|
| `op{shot}` | `{t:'op', k:'shot', ang:0..65535, pow:0..1000, spinV:-1\|0\|1, spinS:-1\|0\|1}` | 出杆。仅 aim 期当前回合席位受理；ang 右移 3 取整（§2.2 sanitize）、pow 钳 0-1000 |
| `op{place}` | `{t:'op', k:'place', x, y}` | ball-in-hand 放白球（milli，§2.5 合法域校验，非法 reject event） |
| `op{concede}` | `{t:'op', k:'concede'}` | 认负 → end{reason:'resign'} |

**下行（ruling + snapshot 双通道）**：

| 消息 | 字段 | 说明 |
|---|---|---|
| `ruling` | `{t:'ruling', frame, turn, phase:'aim'\|'motion', timerMs, openTable, groups:{0,1}, ballInHand, shot?:{seat,ang,pow,spinV,spinS,cue:{x,y}}, events:[…], state}` | 回合裁决+**球动期起点宣告**（shot 字段携带确定性重演所需全部输入）。events：`{k:'turn',seat}`/`{k:'assign',seat,group}`/`{k:'foul',seat,why:F1-F4}`/`{k:'ballinhand',seat}`/`{k:'respot',id}`/`{k:'timeout-shot',seat}`/`{k:'reject',why}` |
| `snapshot` | `{t:'snapshot', frame, base, full, balls:[[id,x,y,potted],…], ext:{physics:{engine,hash,sub}}}` | 球动期 10Hz（§5.2）；静止期仅事件驱动随 ruling 附带 |
| `end` | 协议 §4.2 同形 | reason ∈ `eight-ball\|early-eight\|timeout\|afk\|resign\|abandon`；scores={A:己进球数,B:…} |

`welcome.room.physics = {engine:'pool-int-v1', hash}`（协议 §6 S4 预留位）：hash=fnv1a32(TRIG16+常量表 JSON)，客户端校验不符 → 回退纯插值渲染模式并提示（版本护栏）。

### 5.2 双相状态同步（静止事件驱动 vs 球动 10Hz 追帧——单据指定二式的设计裁定）

- **静止期（aim/resolve）**：状态不变不发帧。变更点（ruling/落袋/换手/ball-in-hand/终局）才发一条 ruling+state（全量 ~1.2KB）。回合制下这是常态——**带宽趋零**。
- **球动期（motion）**：每 50 tick（10Hz）一张 snapshot（16 球位置四元组，~400B/张 ≈ 4KB/s）。作用三合一：①观战/重连客户端的插值源（不跑重演的降级端）；②确定性校验锚（客户端重演至对应 sub 时比对位置，不符即硬同步+上报，§5.4）；③feed 大厅 TV 数据源。
- 快照二式：全量（join/reconnect/sync/每 300 张校准，mmo 范式）带 potted 与完整字段；增量只带活球 [id,x,y]。`base`+缺口检测沿用 S2 范式。

### 5.3 断线重连（当前局面全量 + 回合归属——回合制的天然福利）

- 协议 §2 的 10s+1 拍窗沿用：`join resume{seat,token}` → `welcome`（**全量 state 一次性恢复**：16 球位/分组/回合归属/计时/ball-in-hand/最近一杆输入）。
- **无追帧义务**：回合制无 lockstep 落后补算——球动期断线重连即从当前 snapshot 起播（重演端从最近 ruling.shot 起跑快进至当前 sub，≤5000 子步 <100ms）；静止期重连即即达。恢复 <1s，A5 口径最宽。
- 回合计时**不暂停**（对手等待公平）；逾时席位转 bot 托管（casual 随手杆接管出杆，席位语义同协议——回合制的托管=代打一杆杆）。
- `$sync`/`sync` 纠偏同 welcome 全量路径。

### 5.4 确定性物理（同 seed 同杆法逐字节一致——回放=重放输入序列）

- **同构双端**：sim 是**单源文件**（server 与客户端引同一份 `sim-pool.js`，§2 全整数配方 + TRIG16 烘焙常量）。客户端收到 ruling.shot 即本地重演球动全程（60fps 渲染，零插值），快照比对逐字节一致即自证——**S4 深度要求"确定性物理"的可视化证明每杆都在发生**。
- **输入日志**：`{seed, tickMs, subPerTick, rack, shots:[{frame, seat, ang, pow, spinV, spinS, cue:{x,y}}, …]}`——回放器从 rack 初始态重放 shots 序列即整局（含 Bot 杆：Bot 决策固化在日志，回放不重跑 Bot——S1 范式照搬）。终态 hash（fnv1a32(serialize(state)，键字母序）与在线一致 = 确定性证明。
- **红线清单**（QA 核验口径）：全整数态（milli int32）✓ 量化输入（ang>>3/pow/spin ±1）✓ 固定子步 S=5 ✓ 固定 2 轮碰撞解算 ✓ 固定结算序（§2.4 末）✓ 零 `Math.*` ✓ 零 `Date.now` ✓ serialize 键字母序 ✓ seed=fnv1a32(roomId) 随 welcome 下发、判定路径不消耗（v1 固定阵型，seed 供 Bot rng 与 daily 预留派生）✓。
- **双跑剧本**（A6 断言）：同 seed 同 op 序列跑两房，终态 hash 与输入日志逐字节相等（§6）。

### 5.5 房间生命周期与席位

- seats=2、`teams:{A:[0],B:[1]}`；room tick=10ms、maxTicks=48000。waiting→live→ended 沿用协议；`started` 附初始 state（阵型表 §2.5）。
- 旁观：`join mode:'spectate'` 收同一广播流（ruling+snapshot）——**同帧观战裁判位**（T4-A 落地）：每位旁观者用同一份确定性引擎从同一 ruling.shot 重演，看到的每一颗球轨迹与击球者**逐帧一致**（服务端权威+确定性的白送红利，大厅 TV 招牌内容——创意库原文兑现）。满员旁观无上限软约束沿用平台口径。
- 终局后 8s 展示窗沿用；`end.scores` = 双方进球数（0-7+8）。

### 5.6 延迟容忍、带宽与负载预算

- **200ms 延迟回合制天然容忍论证**（单据指定）：瞄准/力度/旋转三段全部本地计算零上行（§1.4）——瞄准精度与链路延迟**完全解耦**（S1/S2 靠操作面粗粒度豁免瞄准精度，本作是首个真瞄准品类，解法=回合制把连续输入变成一次性 commit，T4-B 创意原文的延迟公平性命题）；commit 是单条 op，200ms 链路下球动可见 ≤~220ms，嵌入 1.5-6s 观球期+10-30s 回合节奏中不可感；对手/观战视角经广播 ≤RTT+100ms。**无逐帧输入、无预测回滚、无和解抖动**——S4 台球行与 S7 弹道行的分工正在于此（预测回滚留给钢铁洪流）。
- **带宽/端**：静止期 ~0（仅 ping/pong 心跳+ruling 事件）；球动期 10Hz×~400B ≈ 4KB/s 峰值——全目录最低档（S1 noop 帧 60B×10Hz 同级、S2 增量常态 0.4KB×10Hz 的单峰脉冲面）。
- **网关负载**：静止房零物理；球动房 500 子步/s × 120 对 ≈ 6×10⁴ 整数对检/s（微不足道）；competitive Bot 前瞻 ≤16×5000 子步/决策 ≤10⁷ 整数运算 <100ms——单进程 50 房 STRESS 口径（roadmap §6 横向）余量充足，QA/STRESS 单按此复核。

- **deterministic 剧本**（A6，S4 首证核心）：api-check 新增 `replayHash` 断言注册（输入日志重放器 + fnv1a32 终态 hash——工具面小改，M1 扩展点 DEV 单实现）。
- 剧本局时序预算：pot-solver 每杆 = 决策 <50ms + 球动 ≤3s（sim 时）/timeScale 8 ≈ 0.4s 墙钟；整局 12-20 杆 ≈ 墙钟 10-20s；三剧本合计（含双跑）<60s——与 slg/mmo/emp 剧本同级。

## 附：设计决策记录（REPORT 引用）

1. **纯整数 500Hz 子步 + 固定 2 轮解算，不用 CCD/事件法**——连续物理的确定性解是"离散到够细"：子步 2ms 使最大闭合位移 5600 milli 落在检测窗 15000 的 2.7× 余量内，隧道不可能发生；固定迭代次数（2 轮 pairwise + 固定结算序）是单据红线，任何"迭代至收敛"式写法都破坏跨端一致。位置 milli-px / 速度 milli-每子步 / 乘子 Q16.16 三层单位一次冻结。
2. **三角烘焙表提交为源码常量**——`Math.sin` 跨端差异是确定性物理最隐蔽的毒（V8 版本间尾数可异）；TRIG16/ATAN8 生成后提交，两端字节一致，sim 路径零 `Math.*`。瞄准角上传 uint16 但入 sim 前 >>3 量化到 0.044°——**精度即协议**：量化边界之后才允许确定性。
3. **瞄准零上行、commit 单条 op**——S4 台球行的延迟哲学：真瞄准品类不做逐帧输入（那是 S7 预测回滚的战场），回合制把瞄准变纯本地几何，200ms 延迟只影响球动可见时刻且被观球期吞没。三段操作（瞄准/力度/旋转）因此全部本地，上行面收窄为 shot/place/concede 三 op。
4. **双相快照：静止期事件驱动、球动期 10Hz**——单据给的二选一（"快照仅在球停后发 vs 球动期 10Hz 追帧"）裁定为**两相并用**：回合制常态是静止（带宽趋零），球动期 10Hz 服务三类消费者（插值降级端/确定性校验锚/feed TV）。10Hz 而非更高：确定性重演端根本不消费快照频率，60fps 画面与 4KB/s 带宽两头全占。
5. **客户端确定性重演为主、插值为降级**——客户端与服务器跑同一份 sim 源文件，收到 ruling.shot 即本地 60fps 重演，快照仅作逐字节校验锚；不符硬同步+上报（bug/版本哨兵）。这使 T4-A 同帧观战、§3.3 回放镜头、A6 双跑断言三件事共享同一机制（确定性），一份投资三处收益。版本护栏：welcome.room.physics.hash 不符 → 回退插值模式。
6. **物理 Bot 双轨：几何解析核 + 服务端前瞻模拟**——连续角域没有格子可搜，balanced 档用 ghost ball 反射几何（整数实现），competitive 档在其上加 scratch 副本前瞻（≤16 次×5000 子步硬帽，<100ms）。Bot 决策同守整数纪律（TRIG16/ATAN8 + 种子化 rng）——不是 sim 确定性要求 Bot，是双跑剧本要求同 seed 同决策。
7. **全量球位无迷雾下发**——单屏 16 球状态 ~1.2KB，辅助线/解算核/观战重演都需要全量；休闲匿名制无排位无作弊威胁面（empire 附决策 8 先例）。DEV 注意：渲染过滤是客户端自由，协议层不裁。
8. **8 球规则收窄为 4 犯规 + 简化定色**——call shot/跳球/破球特殊规则全部不做（v1 有意放弃，§1.3 列明）：每条规则都是 resolve 的一个状态分支，收窄换"犯规判据全部来自 sim 事实账本（§2.6）"的可断言性——F1-F4 四条判据在 api-check 里全是显式字段。
9. **固定阵型零抖动**——开局三角留 100-110 milli 间隙防初始重叠歧义，但不加随机抖动：sim 零随机红线（slg §5.2 先例）优先于"每局破球不同"的花式需求；破球多样性来自玩家/Bot 的杆法差异（角/力/塞 3×1000×3 组合域）。daily 残局（T4-C）将来就是换阵型表+seed 派生，接口已留。
10. **30s 回合计时 + 超时随手杆**——回合制防卡死对照 S5 托管先例：超时不判负而由 casual 人格代打一杆（牌局不断），连续 3 次才 afk 认负（A3 剧本路径）。计时对断线方不暂停——对手等待公平优先。
