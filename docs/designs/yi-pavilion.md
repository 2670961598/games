## 1. 玩法循环

**定位**：一局 3-8 分钟的双人棋类合集（可 Bot 补位）——**五子连珠（15×15）+ 黑白翻转（8×8）+ 连环井字（9×9 井字扩展）三模式合一**，触点落子一个动作打天下（竖屏 375×667）。全部落子服务器裁决（S5 回合权威），断线托管自动走子、棋局不断（T5-A 三作复用）。零隐藏信息：盘面即全部真相——观战零透视、战报全量可回放。

### 1.1 三模式选择论证（单卡三规则，分模式战绩）

**为什么是这三个**：三棋覆盖三类棋感且难度天然梯度——连环井字最易上手（井字是全民规则，扩展只加一条送位规则）→ 黑白翻转（规则一句"夹住就翻"，深度在边角与收官）→ 五子连珠（规则最少、攻杀最深）。品类互补（井字=节奏与陷阱/黑白=转换与位置/五子=攻杀与计算），共享同一操作面（点格落子）与同一协议面（place op），新棋种未来=规则注册表新表项（§5.3，第六模式弹性位）。

| 裁定 | 结论 | 论证 |
|---|---|---|
| 模式入口 | **大厅单卡片 → 模式选择浮层**（三按钮各带一图一句） | gameId 单一（协议/房间/档案一套）；模式是房间参数不是游戏 ID——feed/quick/战绩均按 rule 细分 |
| 模式切换 | **换模式=回大厅重选**（房间创建即绑定 rule，局中不可换） | 对局完整性优先；三模式各自常驻 Bot 房，秒进秒换 |
| 天梯 | **分模式战绩，不做共享天梯** | 匿名访客制无排位载体（创意库 L-11 否决先例）；本地 per-rule 战绩页（胜/负/和+特色统计：最长连/最大子差/占盘数），跨模式仅合计徽记（本地聚合） |
| 快速局 | `quick {gameId, rule, level?}` 秒配 | 每模式独立房池；连战自动换边（§1.3） |

### 1.2 一局时间轴（3-8 分钟；room tick=10ms，maxTicks=60000=10min 硬顶）

```
waiting(10s 攒人/Bot 秒满) ─▶ live 行棋循环 ─▶ 终局（八通道，§1.6）
                              turn(seat) → place(30s 步限) → 结算 → 自动换手
                              黑白无合法手 → 自动 pass（不耗步时）；双 pass → 数子终局
```

| 模式 | 开局 | 中盘 | 终局 | 常见手数 |
|---|---|---|---|---|
| 五子连珠 | 中心/边角布局 | 活三冲四攻防、堵与反堵 | 五连告成/满盘兜底 | 20-60 手 |
| 黑白翻转 | 中央定式、避 X/C 位 | 行动性博弈、角与边争夺 | 收官定型、双方无手数子 | 恰 60 手（4 起子+60 空格，每手占 1 格） |
| 连环井字 | 送位试探、抢中心盘 | 子盘攻防、双威胁/送位陷阱 | 母盘三连/占盘数胜负 | 20-50 手（子盘定盘加速终局） |

节奏预算：每手人类 5-15s（30s 步限），三模式 20-60 手 → **3-8 分钟**；每方总时钟 240s（§2.5）从上面封顶思考总量，maxTicks=60000 是硬顶兜底（罕见到顶：到顶即按当前盘面临时终局判定，§1.6 通道 5）。

### 1.3 先后手与让子

- **席位与执色**：席 0=A 恒执黑先行（对齐 element/tactics 席位惯例，脚本断言稳定）；B=白后行。双方名牌常显「黑先/白后」棋色标。
- **换边机制**：结算页「换边再战」——下一局自动交换执色与先手（quick 连战体验，先后手长期公平的轻量解）。
- **让子（仅五子）**：房间参数 `handicap ∈ {0,2,3}`——N>0 时黑方开局**连放 N 手**（自由互异空格，每手照常走 30s 步限），然后白方起正常交替；0=标准局。仅好友/自建房参数位开放，quick 恒 0。实现=前 N 手 turn 恒为席 0，**零协议新增**（就是连续 N 条 A 席 place op）。
- **黑白/井字不设让子**（设计裁定见附 6）：黑白棋让子会破坏初始四子对称性（规则不成立）；黑白后手理论微优（最后一手归属权）、连环井字先手优势被送位机制天然制衡——两者靠换边机制消化。

### 1.4 回合状态机（服务器权威裁决，S5 第三证）

```
turnStart(seat) → place 校验（RULES[rule].legal） → 落子结算（固定序 §1.5）
   │ 非法 → ruling{reject,why}，回合不变（不换手、不耗步限重置）
   │ 合法 → 胜负检查 → 换手（黑白：己方无合法手自动 pass → 对方；双 pass → 数子终局）
   │ 30s 步限到 → 托管 Bot casual 代走一步（{k:'timeout-move'} 入账本）→ 换手
   └ 连续 3 个全超时步（零 op）→ afk 认负
```

- **单步回合**：一手=一回合。place 成功即自动换手（**无 endTurn op**——棋类的回合切换内生于落子，op 面全目录最小，§5.1）。
- **超时自动走子**（票面原文，托管三层第一层）：30s 步限到点未落 → casual 托管**代走一步**（element/tactics 的整回合代打在棋类细化到单步——粒度更细、接管更轻）；玩家在线则下一手自然接回（无需显式夺回）。托管三层全谱见 §5.5。
- **afk 三分离**（element §1.2 纪律照搬）：超时单步代走 ≠ 托管 ≠ afk——仅连续 3 个全超时步（期间零 op）认负；主动托管（host op）与断线托管不计 afk。
- **棋钟独立走表**：每方 240s 总时钟只在己方行棋时递减，归零判负（reason 'clock'，§1.6）——与 30s 步限双轨：步限保活性（代走），棋钟封顶局时（判负）。

### 1.5 落子结算序（固定——跨端一致的根）

每次 place op 服务器按固定序结算（红线，QA 断言依据）：

```
①校验（rule 合法集/空格/送位窗）→ ②入子 board[cell]=seat+1
→ ③规则结算：五子=无；黑白=8 向夹击翻转（事件 {k:'flip'}）；井字=所在子盘三连判定（{k:'sub'}）
→ ④自动 pass 检查（黑白）：换手后对方无合法手 → {k:'pass'} 再换回；双 pass → 数子终局
→ ⑤胜负检查：五连/母盘三连/数子/满盘 → ended
→ ⑥换手 turn=1−turn，moveNo+1，步限重置 30s
```

**井字扩展（连环井字）规则三则**（其余同井字常识）：

1. **送位规则**：己方落子必须在上一步对手落子**所在小盘格位 (br,bc) 对应的子盘**（对手落在某盘的第 (br,bc) 格 → 己方下一手必须去 (br,bc) 号子盘）；若该子盘已死（已定归属或已满）→ **自由**选任意活盘。首手全盘自由。
2. **子盘判定**：小盘内三连（横/竖/斜）→ 该盘归属落子方（sub=1/2）；满 9 格无三连 → 平死（sub=0，双方不可再落、不计归属）。
3. **母盘胜利**：子盘归属三连（8 线，平死不计）→ 胜；全部 81 格落满且无母盘三连 → 占盘数（归属盘计 1、平死计 0）多者胜，同数 draw。

### 1.6 胜负（八通道，先到者胜，reason 入 end 消息）

| # | 通道 | 判定 | reason |
|---|---|---|---|
| 1 | 五连（五子） | 横/竖/斜连续 ≥5 同色（长连计胜，自由规则） | `five` |
| 2 | 母盘三连（井字） | 子盘归属三连 | `meta` |
| 3 | 占盘数（井字） | 81 格满无大三连 → 归属盘多者胜（同数 draw） | `boards` |
| 4 | 数子（黑白） | 双方连续无合法手 → 盘面子数多者胜（同数 draw；64:0 完封事件 `perfect`） | `count` |
| 5 | 硬顶 | maxTicks=60000 到点 → 即时终局判定：五子=最长连→子数；黑白=即时数子；井字=占盘数（全部先比后平则 draw） | `timeout` |
| 6 | 棋钟 | 某方 240s 总时钟归零 → 对方胜 | `clock` |
| 7 | afk | 连续 3 个全超时步（零 op）→ 认负 | `afk` |
| 8 | 弃局 | concede 认负；全员离线 15s abandon（常态是托管续打，双断且重连窗尽才触达） | `resign` / `abandon` |

## 2. 数值表（全部可执行——DEV 可直接抄 sim 常量表）

### 2.1 基线与量纲（统一棋盘编码，多规则集统一表达的地基）

- **统一棋盘编码**：`board` = Int8 一维数组，长 W·H，格号 `cell = r·W + c`（行优先，row 0 顶=对方侧，席位 B 客户端渲染时 180° 翻转、服务器行号绝对——element §1.3 同款）；值 `0=空 1=黑(A/席0) 2=白(B/席1)`；黑白棋翻转=直接改写格值（无三态）。
- **三规则尺寸**：五子 15×15（225 格）｜黑白 8×8（64 格）｜连环井字 9×9（81 格=3×3 子盘 × 3×3 格）。全整数；无 Q8.8 需求（棋类无乘子——**判定路径连定点乘法都没有**，比 tactics 唯一乘子位更简）。
- **canonical state**（服务器全量，serialize 键字母序）：

```
state = {
  rule: 'gomoku'|'reversi'|'cascade',
  board: Int8[W·H], turn: 0|1, moveNo: int, last: cell|-1,
  handicap: int,              // 五子让子 0/2/3（黑白/井字恒 0）
  clock: {0: ms, 1: ms},      // 每方 240000 起，己方行棋时递减
  passStreak: int,            // 黑白连续自动 pass 计数（≥2 → 数子终局）
  sub: int[9]                 // 井字专属：-1 未定 0 平死 1 A 2 B（其余规则恒全 -1）
}
```

### 2.5 计时与终局兜底（计时制全表）

| 参数 | 值 | 说明 |
|---|---|---|
| 每方总时钟 clockMs | **240000（4:00）** | 己方行棋走表（含托管代走段——托管不暂停钟）；归零判负 reason 'clock' |

## 4. Bot 三档策略（棋类 AI：多规则 Bot 统一框架——规则特征提取器接口）

Bot 走网关 Bot 宿主统一接口（`spawnBot('yi-pavilion', level, rule)`），输出与真人完全相同的 `place/host/concede` op（服务器权威校验，零特例通道）。Bot 算术全整数；rng 仅 casual 决策使用（`botRng[seat] = mulberry32(roomSeed ^ (seat+1)·0x9E3779B9)`，按决策事件序消费——同 seed 同决策，双跑剧本依赖）；balanced/competitive 为**纯 argmax + 固定 tie-break（格序）——零随机**。

**统一框架论证（票面核心）**：决策域与规则域解耦——Bot 宿主一份三档决策机（§4.2-4.4 通用骨架），三规则各实现一个**规则特征提取器** `feat(state, seat) → F` 供决策机消费。加第六棋种 = 新增一个 RULES 表项（含 feat），三档决策机零改动；反之调档位权重不动规则实现——两轴独立演化。

### 4.1 规则特征提取器接口（RULES.feat——DEV 直接抄的接口签名）

```
feat(state, seat) → F {
  score: Int,          // 规则域格局分（own − foe，per-rule 定义）：
                      //  五子 = 连型评分表差（§2.2，own 窗分和 − foe 窗分和）
                      //  黑白 = ΣWGT 差 + 8·行动性差(合法手数) + 4·stab 差（§2.3）
                      //  井字 = 母盘启发权重差（§2.4：归属/中心/一步定盘/三连威胁 − 送位危险）
  winNow: [cell],     // 己方一步致胜点（五子=一步成五格；黑白=空（无数子致胜）；井字=一步定关键盘成母盘三连格）
  mustBlock: [cell],  // 对方一步致胜点（必须堵/争的格；黑白=角空位且对方下轮可占（若可））
  threats: [ {cell, lv} ],  // 己方成型威胁（五子=活三/冲四成点；黑白=角与稳定链；井字=一步可定盘点），lv=分值
  danger:  [ {cell, lv} ],  // 对方威胁（同构，防守权重输入）
  legal: [cell],      // 合法手集（=RULES.legal，决策枚举域）
  counts: {own, foe}  // 子力计数（五子=最长连；黑白=盘面子数；井字=归属盘数）——quip 与终局 scores 共用
}
```

**共享底座反应（三档通用，附决策 9）**：`winNow` 非空 → 必走（取胜）；`mustBlock` 非空 → 必堵（不犯蠢）。这是"规则性反应"而非棋力——casual 也以 30% 概率命中，balanced/competitive 恒执行；档位差在更深的预判与前瞻（§4.3/4.4）。

### 4.2 casual 随手（陪玩档）

- **五子**：候选=现有棋子曼哈顿 ≤2 邻域空格（无棋子则中心 5×5 内）rng 随机——随手但不撒野；30% 概率执行 winNow/mustBlock。
- **黑白**：合法手 rng 随机（天然带夹击）；30% 概率抢角（mustBlock=角时更高防角意识）。
- **井字**：合法手 rng 随机（送位窗内随机格）；30% 概率 winNow/mustBlock。
- 拟人延时 0.8-1.8s/手。预期胜率 vs balanced ~25-35%。

### 4.3 balanced 价值评估（陪玩主力）

**决策机（三模式同骨架）**：枚举 `feat.legal`（五子再收窄到有子邻域 2 格内候选 ~≤60 点；黑白 ≤ 合法手；井字 ≤ 送位窗 9 格或活盘空格）→ 服务器 scratch 副本模拟落子（§2.1 state 克隆，pool/element 克隆先例）→ **ΔV = feat(结果).score − feat(当前).score** → argmax（tie-break 格序固定）→ 执行。预算：五子 ≤60 候选 × 572 窗重扫 ≈ 3×10⁴ 整数评估 <10ms/手；黑白 ≤20 候选 × 64 格重扫 <2ms；井字 ≤9 候选 × 子盘重判 <1ms——30s 步限窗口千倍余量。

- 五子附加：**冲四/活三成型点进 threats**，ΔV 天然偏好连型推进（模拟驱动，不写手写模式——element §4.3 先例）。
- 黑白附加：**行动性项**（8·合法手差）自动避开"翻一大片却送对手全盘好手"的贪吃；角权重 120 由 WGT 主导。
- 井字附加：送位危险 −45 项使随手送位（把对手送进可一步定盘的盘）被系统性回避。

### 4.4 competitive 威胁计算 + 浅层前瞻（竞技档）

balanced 核之上三件套（per-rule 深化——票面"五子=启发式评估+威胁检测/黑白=位置权重+行动性/井字=完美解"的竞技层落位）：

1. **五子·威胁检测前瞻**：对方活三/双活三成型点预判——防守偏置可执行式：`danger 项 lv ≥ 8000（活三以上）时该威胁分 ×11 ÷10`（整数乘后除，向零取整；无 Q8 定点需求，两整数即闭式）；加一层对手最佳应答前瞻（束宽 3：己方 top-3 候选各模拟对手 argmax 应手后再比 ΔV）——防"这手成三下手被双杀"。
2. **黑白·末局完全搜索**：空格 ≤10 时放弃启发，全展开 minimax（α-β + 合法手剪枝，节点上限 10!≈3.6×10⁶、实际远小）**以最终子差最优收官**——竞技档的"完美收官时刻"，单次预算 <200ms；中盘沿用 WGT+行动性+稳定子（角归属后 X/C 稳定化修正 §2.3）。
3. **井字·子盘完美解 + 母盘 2-ply**：子盘内着点恒查 **SUB 完美解表**（§2.4——井字域完美解，票面原文闭式兑现）；母盘层 2-ply（己方候选 × 对手子盘完美解应答）+ 双威胁构造（一手制造两个一步可定盘 +15）。

拟人延时 1.5-2.5s。预期胜率 vs balanced ~65-75%。

### 4.6 托管 Bot（断线/主动托管用，非三档——T5-A 三作复用，倾向继承）

- afk 口径三分离照搬：超时代走不计 afk、托管不计 afk、仅连续 3 全超时步（零 op）认负。

## 5. S5 回合权威协议细节（核心节——多规则集统一 state 表达）

本节在 net-protocol v1.1 冻结框架内落 yi-pavilion 实现细则；**不新增消息类型**（复用 §4.1 join/sync + §4.2 welcome/state/seat/end + §6 S5 扩展位 `t:'op'`/`t:'ruling'`，pool/element/tactics 三作实证）。镜像先例新增游戏级声明块 `welcome.room.duel = {engine:'yi-board-int-v1', rule, hash}`——**一套引擎三规则：hash = fnv1a32(三规则常量表 JSON)**（含 §2.2 连型表/§2.3 WGT/§2.4 SUB 表/计时常量），版本护栏对三模式同时生效（不符 → 客户端提示刷新）。DEV 单随交付回填 net-protocol §6（GAMES-74 O1 文档化先例）。

### 5.1 消息规格（JSON 文本帧）——place 单 op 通行三模式

**上行（op 通道）**：

| 消息 | 字段 | 说明 |
|---|---|---|
| `op{place}` | `{t:'op', k:'place', cell:0..224}` | 落子：cell=r·W+c；校验 RULES[rule].legal（黑白=夹击位/井字=送位窗/五子=空格+让子手序）——**三模式同 payload 同语义，多规则统一的协议面红利** |
| `op{host}` | `{t:'op', k:'host', on:bool}` | 主动托管开关（棋局不断）；on=false 或任意合法 op 即夺回 |
| `op{concede}` | `{t:'op', k:'concede'}` | 认负 → end{reason:'resign'} |

（无 endTurn——一手即一回合，落子成功自动换手 §1.4；无 pick/mulligan 前置相位——waiting 10s 攒人即 live。op 面三消息=全目录最小。）

**下行（ruling 单通道 + end）**：

| 消息 | 字段 | 说明 |
|---|---|---|
| `ruling` | `{t:'ruling', frame, turn, moveNo, seat, rule, timerMs, clock:{0,1}, events:[…], state, quip?}` | 每手裁决+系统事件。events：`{k:'place',seat,cell}\|{k:'flip',cells,n}\|{k:'pass',seat}\|{k:'sub',idx,owner}\|{k:'win-line',cells}\|{k:'timeout-move',seat}\|{k:'turn',seat}\|{k:'host',seat,on}\|{k:'reject',why}`（按 rule 出现，协议层零分支） |
| `end` | 协议 §4.2 同形 | reason ∈ `five\|meta\|boards\|count\|timeout\|clock\|afk\|resign\|abandon`（§1.6 八通道）；scores per rule：五子 {moves,longest,clockMs} / 黑白 {discs,角数,maxFlip} / 井字 {boards,subWins,moves}；quip（§4.7） |

**state（canonical，服务器全量=下发视图）**：§2.1 结构体（board/clock/turn/last/moveNo/handicap/passStreak/sub）——**零隐藏信息，canonical 即广播视图**（见 5.2）。

### 5.2 零快照流 + 零隐藏信息（S5 个性化面的按需收缩）

- **零快照纯事件驱动**（element §5.2 极致档继承）：无 snapshot 消息，状态只在落子/系统事件上跳变，每条 ruling 附全量 state（0.3-1.2KB：board 64-225 格 JSON 数组）；每手 1 条 ruling、静默期仅心跳——与 element 同列全目录最低带宽档。
- **零隐藏信息：个性化收缩为恒等映射**。棋类是完美信息游戏——盘面即全部真相，无手牌可藏（element）、无布置可密（tactics）。**S5 三作个性化谱系就此完备：迷雾（element 按角色裁剪）→ 密置+批量披露（tactics 按相位裁剪）→ 全公开（本作恒等映射）**——sim 的 `personalize(room,ctx,msg)` 钩子保留（rooms 广播层既有机制），本作恒返回原视图；未来残局/暗棋变体（弹性位）可在同一钩子上挂出，协议零变更。
- **观战零透视风险**：全公开信息使观战=对局视图原样转发（join mode:'spectate' 收同一 ruling 流）——观战位天然 TV 面（L-04 轮播接口预留不预支，§8）；QA 注意：观战与对局双方视图逐字节相同可断言（全目录首次可这样断言）。
- 裁决权威：合法性（legal/送位窗/夹击/让子手序）全在服务器，客户端压暗只是引导——reject 回弹（§3.1）。

### 5.3 多规则集统一 state 表达与规则注册表（票面核心：board 编码+规则特征提取）

**规则注册表**（sim 常量，DEV 直接抄的框架）：

```
RULES = {
  gomoku:  { W:15, H:15, confirmTap:true,  init(), legal(s,seat), apply(s,seat,cell), end(s), feat(s,seat) },
  reversi: { W:8,  H:8,  confirmTap:false, init(), legal(s,seat), apply(s,seat,cell), end(s), feat(s,seat) },
  cascade: { W:9,  H:9,  confirmTap:false, init(), legal(s,seat), apply(s,seat,cell), end(s), feat(s,seat) }
}
// 五函数签名：init()→state₀；legal(state,seat)→[cell]；apply(state,seat,cell)→{state',events}
//             end(state)→{winner,reason}|null；feat(state,seat)→F（§4.1 特征提取器，Bot 与客户端辅助层共用）
```

- **统一 board 编码**（§2.1）：三规则同一 Int8 格数组+同一 cell 公式——服务器裁决循环、客户端渲染、stateHash serialize、Bot scratch 模拟四者全部只认这一编码，rule 只改变 W/H 与五函数行为。**多规则=数据不是代码分叉**：回合引擎（§1.4 状态机）、托管、回放、双跑、feed 全部 per-rule 零改动。
- **房间绑定 rule**：`room.params = {rule, handicap}`（创建参数；quick 带 rule、handicap 恒 0）；welcome 声明块携 rule+hash（§5 头部）。
- **规则特征提取进 state 表达**：`feat` 是 RULES 一等公民（非 Bot 私有）——客户端威胁提示（§3.2）与服务器 Bot 消费同一实现（sim.cjs 同源双出口，tactics 先例），两端提示永不漂移。

### 5.4 断线重连与观战位（单据指定口径：全量+观战位）

- 协议 §2 的 10s+1 拍窗沿用：`join resume{seat,token}` → welcome **全量 state 一次性恢复**——board 全盘/双方 clock/turn/moveNo/last/handicap/passStreak/sub/托管标志/rule 声明块。恢复 <1s；board ≤225 格全量恒 <1.5KB（单据"全量"口径本作天然最轻）。
- **观战位**：join mode:'spectate' 收同一 ruling 流（§5.2 零透视）；重连窗尽 → §4.6 倾向继承 Bot 接管直至终局或回归——**棋局不断**；回合计时对断线方不暂停（超时单步代走）。
- 战报回放（T5-A「回来看战报」三作兑现）：end 后输入日志重放（§5.6）逐步演示整局——零隐藏信息使**观战者/断线者看到的重放与在线逐手完全一致**（可断言）。

### 5.5 托管三层（战棋托管三层复用——粒度细化到单步）

| 层 | 触发 | 脑 | 粒度（三作谱系） |
|---|---|---|---|
| ①超时自动走子 | 30s 步限到点零 op | casual 随手 | **单步代走**（element 整回合→tactics 整回合→本作单步——票面"超时自动走子"原文） |
| ②断线/主动托管 | 重连窗尽 / host op | balanced + 倾向继承（attackBias/solidBias 从输入日志复算，§4.6） | 持续接管至终局或回归 |
| ③afk 认负 | 连续 3 全超时步（零 op） | — | 防白嫖；①②不计入 |

- 托管不改 seat.kind（名册稳定）；任意合法 op 或 resume 即夺回；feed/名牌外显「托管」徽标。
- 并发裁决（tactics §5.4 串行语义照搬）：op 按到达序串行；place 与步限超时竞态先到者生效（超时先到则该步转 casual 代走并 `{k:'timeout-move'}` 入账，随后到达的该席 op reject not-your-turn）；重复提交幂等 reject（cell 已占）。

### 5.6 确定性与回放（S5 纪律第三证）

- **零隐藏随机（最强档）**：判定路径零 `Math.random`/`Date.now`——棋类完美信息游戏，**连 element 的洗牌流都没有**；随机只存在于 casual Bot 决策与托管代走（服务端侧消耗，固化为 op 入账本）。seed 派生链：`roomSeed = fnv1a32(roomId)`（测试房用 §6 `seed` 钉死）→ `botRng[seat] = mulberry32(roomSeed ^ (seat+1)·0x9E3779B9)`——先手/让子全是房间参数非随机位（A 恒先手，§1.3）。
- **输入日志**：`{seed, rule, handicap, ops:[{frame, seat, k, cell}|系统事件 timeout-move/pass 标记]}`——回放器按序重放 ops 即整局复算（托管代走与自动 pass 已固化为事件，回放不重跑 Bot——S1 范式三作照搬）。终态 `stateHash = fnv1a32(serialize(state))`（键字母序、board/sub 按格序）与在线一致 = 确定性证明。
- **红线清单**（QA 核验口径）：全整数态 ✓ 判定路径零随机（无洗牌流——比 element 更强一档）✓ 结算序固定（§1.5）✓ seed 派生链冻结 ✓ serialize 键字母序+数组格序 ✓ 零隐藏信息（canonical=广播视图，个性化恒等）✓ 自动 pass/让子手序/送位窗显式入规则函数 ✓ SUB 表冻结入 hash ✓。
- **双跑剧本**（A6 断言）：同 seed 同 rule 两房 → 终态 stateHash 与输入日志逐字节相等。

### 5.7 房间生命周期、带宽与负载预算

- 房间：seats=2、`teams:{A:[0],B:[1]}`；tick=10ms、maxTicks=60000；waiting(10s)→live→ended 沿用协议；终局 8s 展示窗；`end.scores` per rule（§5.1，quip 与分模式战绩判据源）。
- **带宽/端**：每手 1 条 ruling（0.3-1.2KB）+ 静默心跳——全目录最低档（同 element/tactics）；黑白局 60 手全程 <80KB。
- **网关负载**：无逐 tick 模拟（计时器外零计算）、裁决=小整数查表；Bot <10ms/手（competitive 黑白末局搜索单次 <200ms 封顶）——单进程 50 房 STRESS 余量全目录最大档，QA/STRESS 单按此复核。
- **200ms 延迟天然容忍**（pool/element/tactics 三作同源论证再+1）：落子是离散 commit，无逐帧输入、无瞄准精度、无插值——200ms 只体现在 ruling 回执（预落子 0ms 本地兜住手感），一手 5-15s 完全吞没。

## 附：设计决策记录（REPORT 引用）

1. **三规则一套引擎：RULES 注册表五函数（init/legal/apply/end/feat）**——多规则集统一表达的具体形态：board 统一 Int8 格数组+统一 cell 公式，规则差异全部收进每规则五函数；协议面红利=place 单 op 通行三模式（payload 只一枚整数）、ruling 结构同形（events 按 rule 出现、协议层零分支）。回合引擎/托管/回放/双跑/feed 全部 per-rule 零改动；第六棋种=新表项（弹性位）。feat 是 RULES 一等公民——服务器 Bot 与客户端威胁提示消费同一实现（sim.cjs 同源双出口），两端提示永不漂移。
2. **井字扩展=连环井字（Ultimate TTT）**——经典 3×3 先手双方完美下必平、无内容可玩；扩展引入送位规则（上手落位指定本手子盘）把"读对手"变成机制，深度成立且保留井字常识面（新手 5 秒懂）。票面"井字=完美解"在**子盘层闭式兑现**：每个子盘恰是一个经典井字，SUB[19683] 完美解表冻结入常量并计入 engine hash；母盘层启发式+2-ply（全树完美解对 81 格不现实，诚实分层）。
3. **棋钟制（每方 240s 总时 + 30s 步限双轨）而非纯步限**——纯步限下慢棋局可拖到 20 分钟+（60 手×20s），"3-8 分钟"单据口径封不住；每方总钟是棋类惯例（对局钟）且天然封顶思考总量；步限保活性（超时代走不判负）、棋钟判负封局时（clock 通道）——两轨语义分离，快棋档只调两个数（附 12）。
4. **零隐藏信息：个性化面收缩为恒等映射**——S5 个性化谱系三作完备（element 迷雾→tactics 密置+批量披露→本作全公开），personalize 钩子保留恒等；红利：观战零透视（可断言观战=对局视图）、重放=在线逐手、canonical 即广播视图（QA 面最小）；未来暗棋/残局变体在同一钩子挂出，协议零变更。
5. **超时=单步代走（托管粒度细化）**——element/tactics 整回合代打在棋类细化为"超时自动走子"单步（票面原文）：接管最轻、玩家回来零成本（下一手自然接回，无需显式夺回）；连续 3 全超时步才 afk——活性与防白嫖的平衡第三版。
6. **让子分模式裁定：五子 {0,2,3}/黑白不做/井字不做**——五子让子是玩家常识且实现=前 N 手 turn 恒席 0（零协议新增）；黑白让子破坏初始四子对称性（规则不成立——黑白棋的强弱势在收官归属而非先手步数，附 3 计时同理）；连环井字送位机制天然制衡先手（先手每手都在替对手指定战场）。三者共同靠「换边再战」消化先后手长期公平——比引入贴目/pie rule 的规则复杂度低一个量级。
7. **五子保 15×15 标准盘 + 落子两段式**——24px 格低于 44px 触点标准是硬约束，但缩盘到 13 路违背"五子棋=15 路"的玩家预期（识图/口碑双输）；两段式（首点预落 0ms 本地→同格再点确认）是触屏棋类的成熟解，且天然消化误触（异格首点=换预落）。黑白/井字格 ≥39px 单点直落——规则级 UI 参数 confirmTap 进 RULES 表项。
8. **宣纸亮底=全目录首款亮底联机游戏**——十作暗底系中的品类气质差（棋馆 vs 战场），亮底直接做第一识图锚（element/speed"锚独立于底色"先例的反向兑现）；HUD 墨字对比度达 P0/600 要求；圆（天）方（地）双子=棋子形色双编码天然（票面原文），黑白翻转/井字图章共用该编码。
9. **Bot 统一框架=决策域与规则域解耦**——三档决策机（共享底座反应 winNow/mustBlock + casual 随机/balanced ΔV argmax/competitive 前瞻深化）全模式唯一；规则差异经 feat 特征提取器注入（连型表/WGT+行动性/母盘权重+SUB 表）——加第六棋种零改 Bot，调档位权重零动规则实现。mustBlock/winNow 定为"规则性反应"三档共享（casual 30% 概率）：棋类不堵成四点=秒输，这不是棋力是下限；档位差在威胁预判与前瞻深度。
10. **HF `__applied` 闭环回读自证首日**——"登记 13px 实际渲染 10px 缺省字"（canvas 静默忽略非法 font 简写）是 mini-moba/street 两作 VIS 实锤坑；本作把 hudFonts() 自证升级为**登记+ctx.font 回读双值比对**（`__applied:false` 即红线），DEV 单首日交付——票面原文指定，识图复检断言源随单冻结。
11. **A 恒先手（执黑）+ 换边机制，不做 seed 随机先手**——席位稳定保脚本断言稳定（expectWinner 'A' 语义恒定）；先后手公平靠「换边再战」（结算页一键）与让子参数；seed 随机先手会让 A2 剧本依赖 seed 的先手归属，收益（玄学公平感）不抵 QA/剧本面成本。
12. **快棋档/每日残局列弹性位不做**——两者都是"参数与内容"面（计时两参数/残局库设计），v1 先交三规则本体（规则引擎新领域的风险预算留足）；弹性单 #11+ 与 L-05 日历联动（创意库建议口径照抄）。
13. **一套 engine hash 护栏三模式**——hash=fnv1a32(三规则常量表 JSON)（连型表+WGT+SUB 表+计时常量）：多规则统一引擎的版本护栏必须是**单哈希全量覆盖**（三规则各一哈希会造成"模式间版本漂移"的第三态）；rule 字段随 welcome 声明块下发，客户端按 rule 分支渲染。
