# 指尖游戏平台 质量优先重构流程（SOP v1）

> 生效：2026-09-26 ｜ 制作人指令：允许更长周期、更多单据、更高成本，全部游戏按质量优先重做；PM 负责流程设计而非仅完成任务。
> 本文是重构战役的唯一流程事实源；单据模板、验收标准、退回规则以此为准。

## 0. 质量红线（所有游戏的 Definition of Done）

| 维度 | 硬标准 | 验证方式 |
|---|---|---|
| 性能 | 中端机型口径：平均 ≥55fps，5 秒采样掉帧（<30fps）占比 <2%；冷启动 <3s；内存无持续增长 | `scripts/perf-smoke.js` 无头采样，JSON 落盘 |
| 可玩 | 能开始、能赢、能输；输入反馈 <100ms；无死局；难度曲线符合规范档位 | `scripts/play-check.js` 功能断言 + PM 试玩抽检 |
| 合规 | seed 确定性（fnv1a32+mulberry32）；计分公式与规范逐字一致；单拇指 375×667 安全区 | play-check 断言 + 代码审查 |
| 一致 | 引擎统一 Phaser（经 games/_shared/engine.js 适配层）；交互词表、上报协议、视觉基调统一 | 结构检查 + PM 评审 |

**任一维度不过 = 复验退回，不算交付。** 计数不再是验收目标，质量红线才是。

## 1. 五阶段流程

```
P0 引擎基座 ──→ P1 黄金样本 ──→ P2 波次迁移(×8~10波) ──→ P3 横向打磨 ──→ P4 终验交卷
   GAMES-22       2类型打磨至       每波2-3类型            全目录统一走查      全目录报告+制作人试玩
  (已在途)        "值得抄"标准       +每波必配QA环          +薄弱类型二轮       抽样验收
```

- **P0 引擎基座**（GAMES-22，在途）：Phaser 本地化、适配层（seed/tier/安全区/上报）、perf-smoke 工具、play-check 工具雏形。
- **P1 黄金样本**：tap-burst + lane-runner 十款打磨到红线全过，产出"黄金样本"代码范式（场景结构、对象池、固定时步、输入处理的标准写法）。**制作人试玩认可后 P2 才开波**——这是质量基准的对齐点。
- **P2 波次迁移**：22 个剩余类型，每波一张迁移单（2-3 类型）+ 一张 QA 单（该波全量 perf-smoke + play-check + 退回项修复）。**波内串行，波间可依黄金样本迭代范式**。预计 8-10 波。
- **P3 横向打磨**：全目录统一走查（视觉基调、音效预留、 metagame 钩子如星级上报），薄弱类型开二轮专项单（手感/难度调优）。
- **P4 终验交卷**：全目录 125 款 perf-smoke 报告 + play-check 全量报告 + PM 质量整改总结 + 制作人抽样试玩签收。

## 2. 单据分类学（成本上限放开，按需开单）

| 类型码 | 单据 | 触发 | 范围 |
|---|---|---|---|
| ENG | 引擎/基座工程 | 战役阶段需要 | 基座、工具链、适配层 |
| MIG | 类型迁移 | P2 每波 | 2-3 类型×5 档，照黄金样本范式 |
| QA  | 波次质检 | 每波 MIG 交付后 | 全量 perf+play 双报告、退回项修复 |
| FIX | 定点修复 | QA/试玩发现单点问题 | 单类型或单款，小步快跑 |
| FEEL | 手感调优 | 可玩但"不好玩" | 难度曲线、反馈动效、juice |
| VIS | 视觉统一 | P3 | 美术基调、UI 一致性 |

- 同一类型允许多张单接力迭代（MIG→QA→FIX→FEEL 链），**不要求一单到位**。
- 每张 MIG/QA 单必须引用本 SOP 与黄金样本范式；worker 任务书由 PM 按模板生成。

## 3. 每波节奏（以 P2 一波为例）

1. PM 开 MIG 单（2-3 类型，附黄金样本范式引用 + 该类型规范节）→ 预批立项
2. worker：先 `git merge main` → 迁移实现 → 自跑 perf-smoke/play-check 附 REPORT → 交付
3. 框架复验（冻结闸门 + PM 开 QA 单跑全波双报告）
4. 双报告有任何红线项 → FIX 单退回修复（attempt 由批复清零）→ 复验
5. PM 抽检试玩 ≥2 款/波，向制作人简报（含帧率数据表）
6. 全绿 → 合并交付，开下一波

## 4. 度量与升级

- 每波交付简报必含：平均 fps / 掉帧率 / play 通过率 / 退回次数
- 同一类型 FIX ≥2 轮仍不过 → 升级：PM 亲自介入诊断（手感问题）或换实现路径，留证据评论
- 引擎级问题（Phaser 包体/性能不达）→ PM 裁决换引擎，全战役回 P0 重跑基座（预留 PixiJS 备选）

## 5. 诚实预算

- P0-P1：~1 天（含制作人对齐）
- P2：8-10 波 × (1 迁移单 + 1 QA 单 + 0~2 FIX 单) ≈ 25-35 张单，约 3-5 天
- P3-P4：~1-2 天
- 总计约 30-45 张单、5-8 天——高于量产成本数倍，换取的是"每款都拿得出手"。
