### 1.2 聚类结果：三类缺陷族，两个跨游戏共性根因

**簇 C1「无逃逸吸收态」——Bot/决策体挂起死锁，3 例（T1×2 + T2×1）**

slg-F1（经济闸门不可达）、slg-F2（互锁饿死）、mmo-F1（几何轴向楔死）。机制上一经济一几何，形态完全同构：
进入某状态后**不存在任何出边**——wanted 不重掷、克制兵永攒不够、推挤永无侧向分量——系统就地永久挂起，且无超时检测、无自救分支。mmo-F1 甚至是**确定性**的（跨 seed 固定 seat 2/6/7，非 rng 噪声），说明这类缺陷在低倍率短局 QA 里就稳定可测。

> **共性根因 P1：设计书与实现只定义 happy path 的状态转移，不为"进入不可达/无进展状态"定义逃逸路径。** Bot 决策循环没有进展校验（N 拍无进展→换目标/绕行/重掷），资源/几何参数组合也不做可达性钳制（闸门 ≤ 上限）。两链各烧掉一张 FIX 专项单（G45/G54），mmo 侧修复需三层防护+29.6 分钟复测——是两链成本最高的缺陷族。

**簇 C2「语义边界的粒度缝隙」——字面 spec 与实现细节之间，8 例（T1×3 + T2×5）**

slg-F3（"一次性"≠双通道）、slg-F4（scores≠kills）、slg-F5（文案≠真实状态）、mmo-F2（"≤16ms"≠10Hz 节拍）、mmo-F3（弃帧≠不占序号）、mmo-F4（"最坏情形"≠常态形态）、mmo-F1'（席位延续≠玩家直觉）、mmo-F2'（"≤10s"≠10s+1 拍）。

> **共性根因 P2：规格用自然语言承诺语义（一次性/≤10s/≤16ms/最坏情形/积分），实现按自己的量化粒度（通道、节拍、判定点、字段）落地，中间的边界带无人定义。** 8 例全部为低危——被门控、容差或客户端豁免兜住，未发生实际错误结果——说明红线粗度本身合适，但协议/设计书缺"粒度条款"。子模式 P2b 值得单记：**4/8 例的本质是复用既有通道/字段承载新语义**（lastInput 通道泄漏、scores←kills、st.sessions 跨玩家延续、own.id 跨角色裸读[mmo-F5]），复用带来串扰。

**簇 C3「观测面语义」——工具与测试基建，5 例**（工具链行，见 1.1 表）：观测器自身的语义边界（假 200、陈卡竞态、阈值拍脑袋）与隔离基建缺口（存档互写）。不属产品缺陷，但直接哺育 §3/§5 的 SOP 与工具提案。

### 1.3 聚类的可执行推论

- P1 类在 QA 一号阶段 100% 被捕获（两链均 QA1 发现、FIX1 修复）——**QA1 的 Bot 行为实测（逐帧记账+跨 seed）是当前模板里性价比最高的环节，应保持且加码**（见 §4 Bot 红线措辞升级）。
- P2 类 8 例中 5 例是"一行可修"（F3 一行、F1' 一行、F2' 一行、F4 对象换源、F5 文案）——**适合在 FIX 二号低危单里批量收口**，两链实际也是如此走完的；推广 21 款时应在 QA 模板预置"语义边界 checklist"（一次性/序号/字段复用/边界粒度/角色面），把这类发现从"意外"变"例行"。

## 2. O1 跟踪：混编高 churn RSS 高水位爬升——二段复跑判据方案（设计稿，本单不执行）

### 2.1 现状与既有证据（GAMES-65 §6 O1 原文数据）

- 现象：C 组混编（67 次测试房建/收 churn + 每 10s×7 房全量 state 轮询 stringify）RSS **92,256→114,720KB（+22.4MB/5min）**，窗内未达平台。
- 支持"非活泄漏"的反证四条：①A 段前后半均值 **-408KB 负增长**（6 镇并行收敛实证）；②生产 :4400 同代码常驻 **2.5h RSS 57.6MB/CPU 0.8%**；③GAMES-58 混编 30min 版撤池后稳态 **85.7MB**；④QA2(slg) 长局三跑增量单调收敛 **8.0→4.4→1.1MB**。
- 缺口：5 分钟预算窗内未验证"C 段高 churn 画像下 RSS 是否终将平台"——即**未排除慢性活泄漏**，仅有旁证。

### 2.2 二段复跑判据方案（v1，供后续长窗单/STRESS 模板采纳）

**触发条件（先判免跑）**：混编段 +ΔRSS/5min ≤ **10MB** 或该段前后半均值已走平 → 免二段（当前 C 段 +22.4MB 超阈，属应触发）。触发线取 10MB=A 段有界区间宽度（74.9-83.9MB）的量级，避免 GC 锯齿误触发。

**二段协议**（同网关同进程、不清重启，负载画像与 C1 段对齐）：

| 段 | 时长 | 内容 |
|---|---|---|
| C2 | 5min | 复刻 C1 负载（同测试房数/同轮换率/同轮询节奏） |
| D（撤池） | 2min | 停全部测试房 churn，仅留 BotHost 自然负载 |
| 可选仲裁 | 5min | `--expose-gc` 每 30s 强收，采 RSS 地板 |

**判据（判定取段内 ≥0.5Hz 采样的线性回归斜率与半窗均值差，不用首尾差，抗 GC 锯齿；剔除段内房数变化 >10% 的窗）**：

- **J1 平台成立**：C2 增幅 ≤ 0.3×C1 增幅（本例即 ≤6.7MB）且 C2 后半均值−前半均值 ≤ +2MB → 高水位平台实证，O1 关闭。
- **J2 回落成立**：撤池 2min 内 RSS 回落 ≥（C1+C2 爬升量的 50%），或回落至 A 段基线 +20% 以内 → 分配高水位定性成立，O1 关闭（与 G58 撤池稳态 85.7MB 互证口径）。
- **J3 仲裁（可选）**：强收地板与 A 段基线差 ≤15% → 非活堆实锤。
- **失败处置**：J1、J2 双失败 → 判疑似活泄漏，升级独立泄漏专项单（heap snapshot 前后 diff + 逐房归因，独立 30min 预算），不得在原单内"再跑一次看看"。

**预算挂靠**：二段合计 +12min（C2 5min + D 2min + 接力与回落余量 5min）。建议入 §8.5 STRESS 模板作**条件触发段**（只在混编段超触发线时启用；超 20min 转收尾线时降级为独立小单）。

## 3. SOP 进化提案：§8.5 预算模板候选文本

### 3.1 数据论证（预算版 vs 58 号五跑全灭）

| 单 | 任务书预算形态 | 结果 |
|---|---|---|
| G58 STRESS（T1） | 3×30min 串行压测，无预算声明 | **五跑全灭**：三跑触 45min 墙钟 kill、一跑异常死、一跑再触墙断路；PM 亲自组装五跑工件 + worker 第 6 跑复核才收官（案例 Q-007） |
| G59 QA2（T2） | 预算版 45min 总帽 + 每步计时 | **一次过**：串行实测 21.5min ≤25，总交付 45min（spot/feed 并行车道后台化） |
| G65 STRESS（T2） | 预算版 ≤20min 转收尾线/<25min 硬帽 | **一次过**：三组实测合计 18:53，未触发降级；靠交叉引用（四单 ≈98min 长局）代替重跑 |

结论：Q-007 的根因不是 worker 能力，是**任务书预算与单 worker 45 分钟墙钟失配，且超载信号（重定范围评论）在 worker 启动后不可见**。预算版三要素（任务书声明实测窗+分组时长模板+交叉引用代替重跑）在 T2 两单上实证有效，应固化为 SOP 条款而非依赖 PM 个人记忆。
